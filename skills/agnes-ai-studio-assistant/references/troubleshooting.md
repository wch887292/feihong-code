## 启动相关

### 问题1: 启动报错 `ModuleNotFoundError: No module named 'xxx'`

**症状**：执行 `python app.py` 后报缺少某个 Python 包。

**原因**：依赖未安装或安装不完整。

**解决**：
```bash
# 安装所有依赖
pip install -r requirements.txt

# 如果某个包安装失败，单独安装
pip install <package_name>
```

**检查**：运行项目健康检查脚本：
```bash
python scripts/project_check.py
```

---

### 问题2: 启动报错 `Address already in use` 或端口被占用

**症状**：`OSError: [WinError 10048] 通常每个套接字地址(协议/网络地址/端口)只允许使用一次。`

**原因**：5000 端口已被其他进程占用（可能是之前的 Agnes 实例未关闭）。

**解决**：

**方法1：关闭占用进程**
```bash
# Windows 查找占用 5000 端口的进程
netstat -ano | findstr :5000
# 结束进程（替换 <PID> 为实际进程号）
taskkill /PID <PID> /F
```

**方法2：修改端口**
编辑 `app.py`，修改 `app.run(port=5000)` 为其他端口（如 5001），然后访问 `http://127.0.0.1:5001`。

---

### 问题3: 启动后浏览器访问显示空白

**症状**：应用启动成功，但浏览器打开 `http://127.0.0.1:5000` 显示空白或 404。

**原因**：
1. 静态文件路径配置错误
2. `static/index.html` 文件缺失或损坏
3. 浏览器缓存问题

**解决**：
1. 确认 `static/index.html` 文件存在且非空
2. 按 `Ctrl+F5` 强制刷新浏览器（清除缓存）
3. 查看控制台是否有报错信息
4. 尝试使用无痕模式访问

## API 配置相关

### 问题4: 所有 API 调用都返回 401 未授权

**症状**：生成图片/视频时报错 "API Key 无效" 或 HTTP 401。

**原因**：
1. 未配置 API Key
2. API Key 错误或已过期
3. 使用的模型未在对应平台开通

**解决**：
1. 打开设置界面（右上角 ⚙ 图标）
2. 确认已配置对应厂商的 API Key：
   - Agnes 模型 → 主 API Key
   - 豆包模型 → 豆包 API Key（或配置豆包 Pool）
   - DeepSeek 模型 → DeepSeek API Key
   - 千问模型 → 千问 API Key
   - MiniMax 模型 → MiniMax API Key
3. 确认 API Key 复制完整（通常以 `sk-` 开头）
4. 登录对应平台，确认 API Key 状态为"启用"且账户有余额

---

### 问题5: 豆包模型报"模型未授权"

**症状**：使用豆包 Seedream / Seaweed 模型时报错 "model not authorized" 或 "模型未开通"。

**原因**：豆包的文本、图片、视频模型需要**分别开通**，只开通一个会导致其他模型不可用。

**解决**：
1. 登录 [火山引擎方舟平台](https://www.volcengine.com/product/ark)
2. 进入「模型广场」
3. 分别搜索并开通：
   - 文本：豆包 Pro 32K / 豆包 Lite 32K
   - 图片：豆包 Seedream 3.0
   - 视频：豆包 Seaweed T2V
4. 每个模型点击「开通」按钮
5. 等待 5-10 分钟后重试

---

### 问题6: 豆包 Pool 不生效

**症状**：配置了 `doubao_pool`，但控制台没有 Pool 相关日志，还是用的单 Key。

**原因**：
1. `doubao_pool.enabled` 未设置为 `true`
2. 配置后未重启应用
3. JSON 格式错误导致配置未加载

**解决**：
1. 检查 `config.json` 格式是否正确（可用 JSON 校验工具验证）
2. 确认 `"enabled": true`（注意是布尔值，不是字符串）
3. 重启应用（`python app.py`）
4. 调用一次豆包模型，查看控制台是否有：
   ```
   [豆包Pool] 使用 domestic 区域 Key: sk-xxxxxxxx...
   ```

**正确配置示例**：
```json
{
  "doubao_pool": {
    "enabled": true,
    "domestic": {
      "base_url": "https://ark.cn-beijing.volces.com/api/v3",
      "keys": ["sk-你的Key"]
    }
  }
}
```

## 图片生成相关

### 问题7: 图片生成一直 pending 或超时

**症状**：点击生成图片后，长时间没有结果，或报超时错误。

**原因**：
1. API 端点不可达（网络问题）
2. 模型服务繁忙，排队时间长
3. API Key 限流（QPS 限制）
4. 提示词过长或包含违规内容

**解决**：
1. 检查网络连接，确认能访问 API 端点
2. 等待 1-2 分钟后重试
3. 查看控制台日志的请求详情和错误信息
4. 简化提示词，避免过长
5. 如果是豆包模型，确认账户有余额，未触发限流

---

### 问题8: 生成的图片与提示词不符

**症状**：生成的图片内容与描述差距很大。

**原因**：
1. 提示词不够具体或包含歧义
2. 模型理解偏差
3. 负面提示词缺失

**解决**：
1. 优化提示词，包含：主体 + 环境 + 风格 + 光线 + 构图 + 画质
   - 差："一只猫"
   - 好："一只橘色英短猫坐在窗台上，午后阳光斜射，背景是虚化的绿植，写实摄影风格，8K高清，浅景深"
2. 添加负面提示词："模糊,低质量,变形,多余的手指,文字,水印"
3. 尝试不同的模型（ Agnes Image / 豆包 Seedream / MiniMax ）

## 视频生成相关

### 问题9: 视频生成失败，报 "duration" 相关错误

**症状**：视频生成时报错 "duration must be between X and Y"。

**原因**：请求的视频时长超出模型支持范围。

**解决**：
1. 不同模型支持的时长不同：
   - Agnes Video：5-18 秒
   - 豆包 Seaweed：5-10 秒
   - MiniMax H3：5-10 秒
2. 将时长调整到支持范围内
3. 短剧生成的 `shot_duration` 可选 5 / 10 / 18 秒

---

### 问题10: 视频生成完成但没有声音

**症状**：视频可以播放，但没有音频。

**原因**：
1. 当前视频生成模型默认生成无声视频
2. 数字人口播模式下，TTS 配音生成失败
3. ffmpeg 合成时音频流丢失

**解决**：
1. 普通文生视频：当前版本视频模型默认无声，属于正常现象
2. 数字人口播：
   - 确认 `use_tts = true`
   - 查看控制台 TTS 生成日志
   - 确认系统有中文字体（字幕烧录需要）
3. 检查 ffmpeg 是否正常安装：
   ```bash
   ffmpeg -version
   ```

## 短剧生成相关

### 问题11: 短剧生成卡在某一步不动

**症状**：短剧进度停在某个步骤（如 step1 / step3），长时间没有进展。

**原因**：
1. 文本模型生成超时（小说/剧本内容较长）
2. 图片生成排队或失败
3. 视频生成失败未正确处理
4. 应用卡死

**解决**：
1. 查看控制台日志，确认当前卡在哪个具体请求
2. 如果是文本生成超时：
   - 小说类型选择"小小说"或"短篇小说"（字数少，生成快）
   - 更换更快的文本模型（如 agnes-2.5-flash / doubao-lite-32k）
3. 如果是图片生成失败：
   - 在 `paused` 状态下，点击失败素材的"重新生成"
   - 或点击"重新提取素材并生成三视图"按钮
4. 如果应用完全卡死：
   - 关闭应用（Ctrl+C），重新启动
   - 已生成的文件保留在输出目录，但任务状态会丢失

---

### 问题12: 短剧小说生成内容乱码或格式错误

**症状**：小说内容显示为乱码，或 JSON 解析失败。

**原因**：
1. 文本模型返回格式不符合预期
2. 编码问题
3. 模型生成了 Markdown 格式但未正确清理

**解决**：
1. 在小说确认界面，点击「编辑小说」手动修正内容
2. 或使用文件导入功能，导入自己写好的小说（.txt / .md）
3. 更换更稳定的文本模型
4. 如果是 JSON 解析错误，查看控制台的原始返回内容

---

### 问题13: 短剧合并视频失败

**症状**：所有镜头视频生成完成，但合并时报错。

**原因**：
1. 成功的镜头不足 2 个
2. ffmpeg 合并参数错误
3. 视频编码格式不一致

**解决**：
1. 确认至少有 2 个镜头成功生成
2. 查看控制台 ffmpeg 错误日志
3. 尝试使用"自定义合并"功能，选择部分成功的镜头合并
4. 如果只有 1 个镜头成功，可以直接在输出目录找到该镜头视频使用

## 数字人口播相关

### 问题14: 数字人口播语音混乱听不清

**症状**：A 模式（静态形象图）生成的口播视频，语音混乱、有杂音、听不清。

**原因**（已在 v2 修复）：
- I2V 图生视频生成的视频自带音频，与 TTS 音频混合导致混乱

**解决**：
1. 确认使用的是最新版本（已修复：ffmpeg 添加 `-an` 参数去除视频原音频）
2. 如果还是有问题：
   - 尝试 `use_tts = false`（使用视频模型自带语音，对口型更自然）
   - 或更换 TTS 音色
3. 确认文稿内容清晰，没有生僻字或特殊符号

---

### 问题15: 数字人口播字幕不显示或乱码

**症状**：生成的视频没有字幕，或字幕显示为方框/乱码。

**原因**：
1. 系统没有中文字体
2. ffmpeg drawtext 滤镜参数错误
3. 字幕文本过长被截断

**解决**：
1. **安装中文字体**（Windows 通常已自带）：
   - 确认 `C:\Windows\Fonts\` 下有中文字体（如 msyh.ttc / simhei.ttf）
   - 代码会自动查找 `_find_chinese_font()`
2. 如果还是乱码：
   - 手动安装微软雅黑或黑体字体
   - 重启应用
3. 字幕长度限制为 300 字/段，过长会被截断

---

### 问题16: 数字人口播 C 模式提示词输入框太小

**症状**：C 模式（AI 生成画面）的画面风格提示词输入框只有 3 行，不方便输入长提示词。

**原因**（已在 v2 修复）：
- 原输入框 `rows="3"`，与文稿窗口（`rows="8"`）尺寸不一致

**解决**：
1. 确认使用最新版本（已调整为 `rows="8"`，`min-height:160px`，与文稿窗口一致）
2. 如果还是旧版本，手动编辑 `static/index.html`：
   - 搜索 `anchorVideoPrompt`
   - 将 `rows="3"` 改为 `rows="8"`
   - 添加 `style="min-height:160px;"`

## 前端界面相关

### 问题17: 前端界面显示异常，样式错乱

**症状**：页面布局错乱、按钮重叠、文字溢出。

**原因**：
1. 浏览器缓存了旧版本 CSS/JS
2. `index.html` 文件被修改后格式损坏
3. 浏览器兼容性问题

**解决**：
1. 按 `Ctrl+F5` 强制刷新（清除缓存）
2. 尝试使用 Chrome / Edge 浏览器（推荐）
3. 如果修改过 `index.html`，检查是否有未闭合的 HTML 标签
4. 从 git 恢复原始版本（如果有版本控制）：
   ```bash
   git checkout -- static/index.html
   ```

---

### 问题18: 新增的功能按钮不显示或点击无反应

**症状**：新增的按钮（如"重新提取素材"、"更新参考图"）不显示，或点击后无反应。

**原因**：
1. 浏览器缓存
2. JS 函数未定义或拼写错误
3. HTML 元素 ID 不匹配

**解决**：
1. `Ctrl+F5` 强制刷新
2. 按 `F12` 打开开发者工具，查看 Console 是否有 JS 报错
3. 检查 `static/index.html` 中：
   - 按钮的 `onclick` 函数名是否正确
   - 对应 JS 函数是否存在
   - 元素 ID 是否与 JS 中引用的一致

## 打包发布相关

### 问题19: PyInstaller 打包失败

**症状**：执行 `build.bat` 或 `pyinstaller build.spec` 时报错。

**原因**：
1. 依赖未安装完整
2. PyInstaller 版本不兼容
3. 动态导入的模块未被正确识别
4. 资源文件路径配置错误

**解决**：
1. 升级 PyInstaller：
   ```bash
   pip install --upgrade pyinstaller
   ```
2. 确认所有依赖已安装：
   ```bash
   pip install -r requirements.txt
   ```
3. 查看打包错误日志，确认缺失的模块
4. 在 `build.spec` 的 `hiddenimports` 中添加缺失的模块
5. 清理旧的构建文件后重新打包：
   ```bash
   rmdir /s /q build dist
   pyinstaller build.spec --clean
   ```

---

### 问题20: 打包后的 EXE 运行报错找不到文件

**症状**：打包后的 EXE 启动时报错 "No such file or directory" 或找不到 `static/index.html`。

**原因**：
1. PyInstaller 未正确打包静态资源文件
2. 代码中使用了相对路径，但 EXE 运行时工作目录不同
3. `_MEIPASS` 临时目录处理逻辑缺失

**解决**：
1. 检查 `build.spec` 的 `datas` 配置，确认包含了 `static/` 目录：
   ```python
   datas=[('static', 'static')],
   ```
2. 确认代码中有处理 PyInstaller 路径的逻辑：
   ```python
   import sys
   import os
   if getattr(sys, 'frozen', False):
       base_dir = sys._MEIPASS
   else:
       base_dir = os.path.dirname(os.path.abspath(__file__))
   ```
3. 重新打包，确认 `dist/` 目录下包含 `static/` 文件夹

## 通用排查步骤

遇到任何问题，按以下顺序排查：

1. **查看控制台日志**：应用运行的终端窗口会输出详细的错误信息和堆栈
2. **查看浏览器 Console**：按 `F12` 打开开发者工具，查看前端 JS 报错
3. **运行健康检查**：
   ```bash
   python scripts/project_check.py
   ```
4. **确认配置正确**：检查 `config.json` 格式和 API Key
5. **重启应用**：关闭后重新启动 `python app.py`
6. **强制刷新浏览器**：`Ctrl+F5`
7. **查看输出目录**：确认生成的文件是否存在

如果以上步骤都无法解决，记录以下信息后寻求帮助：
- 错误信息（完整堆栈）
- 复现步骤
- 使用的模型和参数
- 操作系统和 Python 版本
- `config.json` 配置（隐藏 API Key 后）
