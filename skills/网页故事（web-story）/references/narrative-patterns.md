# 叙事骨架库 — 选题 → 章节拆分

选题到手，先判断属于哪一类骨架。四类骨架覆盖绝大多数"把一个主题做成网页"的需求；混合型按主骨架走，嫁接另一类的一两个章节。

通用规则：

- 5~9 个章节，每章只讲一个论点；超过 9 个就合并。
- 第一章之前必须有 hero：一句话说清"这是什么 + 为什么值得看"。
- 最后一章给行动：转发、报名、关注更新，或"怎么自己验证"。
- 每章的事实标来源口径（官方/财报/社区/估算），不虚构数据。

## 骨架 A：研究观察站

适合：持续追踪一个行业或主题。

1. Hero：这个领域现在处于什么阶段，一句话定调
2. 大图景：产业链/生态结构，帮读者建立地图
3. 关键进展时间线
4. 核心玩家墙：公司/项目卡片，每个一句话定位
5. 争议与反面信号：多空观点并列
6. 数据快照：表格 + 数据时点
7. 接下来看什么：关键节点
8. 方法论与来源

要点：差异化在于防混淆——每条大新闻能回答"具体是什么、到什么阶段、在链条哪一环、真实传导是什么"。

## 骨架 B：指南/榜单

适合：前瞻预测、Top N 推荐、选购/目的地指南。

1. Hero：这份榜单回答什么问题，怎么评出来的
2. 总榜一览（卡片或表格）
3. 评选方法：维度与权重
4. 分维度榜
5. 逐个详解，证据支撑
6. 候选池：展示筛选过程
7. 使用建议：不同读者怎么用
8. 来源与免责声明

要点：预测类内容必须在显眼处标注"这是预测，非官方结论"。

## 骨架 C：项目/网站介绍

适合：介绍一个产品、工具、课程、活动。

1. Hero：一句话价值主张
2. 痛点：没有这个之前问题是什么样
3. 是什么：核心机制，30 秒能懂
4. 怎么用：3~4 步流程
5. 里面有什么：功能/内容模块
6. 谁在用/效果如何：真实案例
7. 常见问题
8. 行动：怎么用/报名/联系

要点：价值主张必须具体，拒绝"赋能""一站式"这类空话。

## 骨架 D：课件专题页

适合：把一节课或一个专题做成可回看的网页。

1. Hero：这节课解决什么问题
2. 学习地图：全课结构一屏看完
3. 核心概念：每个概念一节配例子
4. 方法/流程拆解
5. 案例演示
6. 常见误区
7. 练习/作业
8. 延伸阅读

要点：课件页是给人回看的，每节自包含。

## 拆完之后的自检

- [ ] 每章标题是一句论点，不是"介绍""详情"这种空词
- [ ] 删掉任何一章叙事都不完整；加任何一章都多余
- [ ] 事实清单已列出，每条有来源
- [ ] 手机上一屏能看完 hero 的核心信息
