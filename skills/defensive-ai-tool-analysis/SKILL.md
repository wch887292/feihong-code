# 双用途AI攻防工具·防御视角拆解

> 适用范围：自主渗透智能体、AI 红队/蓝队框架、自动化漏洞挖掘平台等"能力可被攻防双向使用"的 AI 工具。
> 一句话：把"对手的武器"拆成"我们的防御清单"。

## 触发
- 用户给出某款攻防类/渗透类/红队类 AI 工具的项目地址、GitHub 仓库或在线 Demo，要求"分析架构 / 拆解 / 研判 / 防御视角"。
- 关键词：ARTEX、自主渗透智能体、AI 红队、自动化渗透、攻防框架、双用途安全工具、渗透Agent。

## 核心原则（红线，先读再做）
1. **仅防御视角**：架构剖析、威胁建模、合规研判、授权范围内自检方法论。
2. **绝不**：协助获取、部署、运行、武器化该工具，或针对任何未授权第三方系统开展攻击、渗透、破解。
3. **授权铁律**：任何以该类工具开展的安全测试，必须书面授权、限定资产范围、全程留痕；遵守《网络安全法》《数据安全法》，与作者声明（仅限个人学习/代码研究/本地技术验证）保持一致。

## 执行步骤
1. **现状核实**
   - 仓库/页面是否存活：`curl -o /dev/null -w "%{http_code}"` 测 HTTP 码；GitHub 用 `api.github.com/repos/<owner>/<repo>` 确认 404/下架/闭源。
   - 抓取信息源：官方 README/技术博客（Wayback/网页缓存）、安全厂商报告（如 CrowdStrike）、权威媒体转述。
2. **技术栈与运行形态**
   - 后端语言、前端、数据库（是否用图数据库）、Agent SDK、内置工具（nmap/nuclei/curl/bash/http 等）。
   - LLM 接入方式（BYO-key / 任意 OpenAI 兼容端点），部署形态（单体二进制 / Docker Compose）。
   - 扩展机制：MCP、Skills、Memory、流量记录代理、工具审批门。
3. **核心架构拆解**
   - 数据模型（如"双图"：资产图=全局共享；探索图=任务独立、记录攻击血缘）。
   - 多智能体角色：规划者 Planner（全局唯一，按依赖派单，保证链路有序）↔ 执行者 Worker（多实例并行、原子领取、复用彼此日志）。
   - 执行闭环：派单 → 执行工具 → 结果入库更新双图 → 再评估迭代，直到目标达成或无新攻击面。
4. **人在环路（Human-in-the-loop）设计**
   - 审批门/拦截、hint/steer/kill 等控制手段；及其被故意绕过的失效教训（护栏挡不住违规的人）。
5. **真实在野利用映射（若已发生）**
   - 两服务器/跳板架构、模型后端、侦察入口弱点（暴露的公网业务系统）、攻击者 OPSEC 失败（开放目录暴露会话/配置/记忆）。
   - 提取 IOC（关联 IP / 代理 IP / 可疑域名）作为防御封禁与日志回溯清单；明确标注"仅用于防御，不代表对任何人定性"。
6. **防御对策（核心交付）**
   - 能力 → 攻击面 → 对策 映射表。
   - 行为化检测：高速 + 低错误率 + 逻辑连贯遍历，区别于传统噪声扫描器（关注 WAF/API 日志中"低错+深度功能探索"组合）。
   - 加固清单：公网暴露面收敛、API 速率限制/节流、Egress 出网过滤、网络分段与微隔离、零信任、NIST CSF 2.0 + NIST AI RMF。
7. **产出**：Markdown 拆解文档 + 内联架构图（SVG，分层：仪表盘→后端多智能体→双图库→外部大模型），落款带署名三行（公司 / 中心 / 负责人）。

## 参考案例：ARTEX（Autumn-27/ARTEX）
- **定位**：开源 AI 自主渗透测试系统，AGPL-3.0；2026-07-26 发布，2026-10-08 作者宣布闭源停更、仓库下架。
- **技术栈**：Go 单体二进制（内嵌前端）+ Next.js 仪表盘 + PostgreSQL（用关系表实现图存储，非 Neo4j）；Norma SDK 调度 LLM（内层 ReAct 由 Norma Harness 进程内实现）；内置 nmap/nuclei/curl/bash/http；BYO-LLM 任意 OpenAI 兼容端点。
- **双图模型**：
  - Asset Graph（全局共享）：根域名、子域、IP、端口、服务、Web 应用、接口端点；存指纹/版本/归属/去重。
  - Exploration Graph（任务独立）：goal/intent/fact/finding/hint，记录攻击链路血缘，支撑 Planner 判下一步、避免重复与错序。
- **多智能体**：Planner（全局唯一，维护待办、按依赖派单，链路有序 资产测绘→端口扫描→指纹→漏洞探测→利用）→ Worker（多实例并行、原子领取、复用历史日志减重复扫描）。
- **人在环路**：审批门（人工确认）+ hint/对话/直投意图/steer/kill；事件中攻击者绕过。
- **真实攻击（CrowdStrike 取证）**：两服务器——`38.244.50[.]120` 托管 ARTEX 实例 + 开放目录；香港 IP 为主基础设施；模型 DeepSeek v4.1-flash + GLM-5.3 + Grok 4.6；入口为暴露公网业务系统（贷款进度查询服务、员工移动办公系统）；攻击者把含中文渗透提示词的 CLUDE.md、会话历史、记忆丢在开放目录（OPSEC 失败，最大可归因破绽）。
- **IOC（防御狩猎用）**：关联 IP `38.244.50[.]120`；代理 IP `101.53.80[.]20 / 205.214.59[.]31 / 124.155.252[.]63 / 154.201.79[.]246 / 23.248.249[.]90 / 23.158.220[.]98 / 103.248.148[.]84 / 203.160.133[.]172 / 209.209.85[.]38`；域名 `xcai[.]pro`（疑似 DeepSeek 转售）。
- **防御抓手**：行为化检测、暴露面收敛、API 速率限制、Egress 管控、微隔离；假设对手正用 AI 持续扫边界。

- 防御对策：能力→攻击面→对策 映射表 + 行为化检测 + 加固清单
