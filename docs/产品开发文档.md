## 1. 产品概述

### 1.1 产品定位（一句话）

**飞虹 Code 是一款运行在终端的 AI 编程智能体：用户用自然语言描述需求，它自主完成「规划 → 写码 → 执行 → 验证」的完整软件工程任务，并通过多子代理并行与长时任务恢复机制，在大型代码库中稳定交付。**

### 1.2 背景与动机

- Meta 于 2026-08 发布 **Muse Code**（终端 AI 编程 Agent，基于 Muse Spark 1.2），对标 Claude Code / OpenAI Codex，主打多智能体并行、长时任务、仓库级代码变更，并采用低价按量付费策略（贡献者套餐便宜逾 10 倍，但需授权数据留存）。
- 该形态验证了「终端 Agent 自主完成完整软件工程任务」的市场价值，但**闭源、依赖 Meta 模型、数据留存策略对国内企业不友好**。
- 飞虹 Code 的目标：**参照其能力范式，复刻一套自主可控、模型可切换、数据不出域、可私有化部署的终端编程智能体**，复用本团队 TS/Node 工程能力与飞扬企源企业管理方法学。

### 1.3 参照对象能力拆解（Muse Code）

| 能力维度 | Muse Code 实现 | 我们是否复刻 | 我们的差异点 |
|----------|----------------|--------------|--------------|
| 安装方式 | 单命令 `curl … | bash` | ✅ | 增加 `npm i -g` / 国内镜像源 |
| 多智能体并行 | 主代理 + 多个持久化子代理，隔离 worktree 并行 | ✅ | 子代理角色可配置（规划/编码/审查） |
| 长时任务与崩溃恢复 | 本地事件日志作为单一可信源，可精确回放 | ✅ | 事件日志可导出/审计，支持断点续跑 |
| 内置技能 | `/plan`、`/grill`、`/goal` 等 | ✅ | 扩展为可插拔技能市场（本地+团队共享） |
| 多模态输入 | 视频/文档 → 完整应用 | 🔲 P2 | 先支持图片/文档，视频后置 |
| 模型绑定 | 绑定 Muse Spark | ❌ | **多模型路由层**，不绑定单一厂商 |
| 数据策略 | 低价套餐需授权数据留存 | ❌ | 默认本地/私有部署，数据不出域 |
| 透明度 | 完全可审计 | ✅ | 增加变更 diff 可视化与回滚 |

### 1.4 目标用户

1. **专业软件工程师 / 架构师**：处理大型代码库重构、跨模块迁移。
2. **技术团队负责人**：把重复性编程任务自动化。
3. **AI 研究人员 / 独立开发者**：需要长时迭代优化（如 GPU 内核调优）。
4. （远期）**非技术业务人员**：通过自然语言生成内部工具/页面。

### 1.5 核心价值主张

- **自主可控**：模型、数据、部署全链路可私有化，不绑定任何云厂商。
- **成本最优**：多模型路由按任务/成本/能力自动选优，避免为简单任务付高价。
- **稳交付**：长时任务事件日志 + 崩溃恢复 + 隔离 worktree，大型任务不中断。
- **可审计**：每一次模型调用、工具执行、文件变更可追溯、可回滚。

### 1.6 与参照的差异总结

> 不追「模型最强」，而追「架构最稳、可控性最高、成本最优、最贴合国内企业私有化诉求」。

### 2.1 功能全景图

```

│   └── 审批确认（危险操作时）
├── 编排层（Agent Orchestrator）
│   ├── 任务分解 → 子代理派发
│   ├── 子代理并行（隔离 worktree）
│   └── 结果汇总与冲突协调
├── 工具层（Tool System）

│   ├── 执行：run_shell（沙箱+审批）
│   ├── 检索：codebase_search / web_fetch
│   └── 验证：test_run / build_check
├── 模型层（Multi-Model Router）
│   ├── OpenAI 兼容 API（DeepSeek/通义/OpenRouter…）
│   ├── 本地模型（Ollama）
│   └── 路由策略：能力/成本/延迟
├── 运行时（Runtime）
│   ├── 事件日志（单一可信源）
│   ├── 会话/子代理状态

    └── 可插拔技能（本地 + 团队共享）
```

### 2.2 优先级

| 等级 | 功能 | 说明 |
|------|------|------|
| **P0（MVP）** | 终端 REPL、自然语言→代码、文件读写编辑、shell 执行（带审批）、基础规划、模型路由（单/多供应商切换）、事件日志、结构化错误/日志 | 能完成「描述需求→生成并验证代码」的最小闭环 |
| **P1** | 多子代理并行 + 隔离 worktree、长时任务崩溃恢复、技能系统（/plan /grill /goal）、成本计量、diff 可视化与回滚 | 对标 Muse Code 核心差异化能力 |
| **P2** | 多模态输入（图片/文档→应用）、技能市场、团队共享配置、Web 管理面板（可选）、自动 PR 提交 | 增强与生态 |

### 2.3 核心用户故事

- **US-1（开发者）**：`fhcode "把 src/utils 里的 date 格式化抽成独立模块并补单测"` → 自动规划、改码、跑测试、汇报结果。
- **US-2（长时任务）**：`fhcode "对 CUDA 内核做 24h 迭代优化"` → 事件日志持久化，进程崩溃后 `fhcode resume` 从断点续跑。
- **US-3（并行）**：`fhcode "同时给登录/支付/报表三个模块加审计日志"` → 派发 3 个子代理，各自隔离 worktree 并行，合并无冲突。

## 3. 技术架构

### 3.1 总体架构（分层）

```
┌─────────────────────────────────────────────┐
│  CLI 入口 (src/cli)                          │  argparse / REPL / 单命令
├─────────────────────────────────────────────┤
│  Agent 编排层 (src/agent)                     │  Orchestrator / Planner / SubAgent
├──────────────┬──────────────┬───────────────┤
│ 工具层        │ 技能层        │ 模型路由层     │  ToolSystem / SkillSystem / ModelRouter
│ (src/tools)  │ (src/skills) │ (src/models)  │
├──────────────┴──────┬───────┴───────────────┤
│  运行时 / 存储层 (src/runtime)               │  事件日志 / 会话状态 / 恢复
├─────────────────────────────────────────────┤
│  基础设施 (src/shared)                        │  config / errors / logger / types
└─────────────────────────────────────────────┘
```

### 3.2 分层职责（铁律）

| 层 | 职责 | ❌ 禁止 |
|----|------|---------|
| CLI | 解析参数、启动 REPL、渲染输出、收集审批 | 写业务/模型逻辑 |
| Agent | 任务分解、调度子代理、汇总 | 直接调用模型 HTTP / 直接碰文件系统 |
| Tool | 单条能力的纯实现（带 schema + 沙箱） | 跨工具编排 |
| Model | 统一 chat/stream 接口 + 路由 + 成本计量 | 感知业务语义 |
| Runtime | 事件日志、状态、恢复 | 业务逻辑 |
| Shared | config/errors/logger/types | 业务代码 |

### 3.3 多模型路由层设计

**目标**：不绑定任何厂商，按「能力 / 成本 / 延迟 / 任务类型」动态选模型。

```
ModelRouter
  ├─ registerProvider(OpenAICompatibleProvider)   // DeepSeek / 通义 / OpenRouter
  ├─ registerProvider(LocalOllamaProvider)
  └─ route(task: ModelTask): Provider
       策略：
         - capability: code-gen | reasoning | long-context | vision | cheap
         - cost-ceiling: 本次任务预算上限
         - fallback: 主选失败自动切次选
```

- `ModelTask` 携带 `capabilityTags`、`maxCost`、`requireStream`、`contextWindow` 等元数据。
- 每次调用记录 `tokenUsage` 与 `cost` 进事件日志，支持成本计量与告警。
- 配置化供应商清单，密钥仅存于环境变量（`.env`，不入库）。

### 3.4 工具系统（Tool System）

每个工具实现统一契约：

```typescript
interface Tool {
  name: string;                 // 唯一名，如 "edit_file"
  description: string;          // 给模型看的用途说明
  inputSchema: JSONSchema;      // 输入校验（Zod/JSON Schema）
  risk: 'safe' | 'shell' | 'destructive';
  execute(input: unknown, ctx: ToolContext): Promise<ToolResult>;
}
```

| 工具 | 风险级 | 说明 |
|------|--------|------|
| read_file / list_files / grep | safe | 只读，免审批 |
| write_file / edit_file | safe* | 写文件，记录 diff 可回滚 |
| run_shell | shell | 默认需审批/沙箱，危险命令拦截 |
| web_fetch | safe | 联网检索，受白名单限制 |
| test_run / build_check | shell | 触发验证，结果回流 |

### 3.5 运行时事件日志（单一可信源）

- **Append-only** 事件流，是长时任务可回放/恢复的基础。
- 事件类型：`session_start` / `model_call` / `tool_call` / `approval` / `file_edit` / `error` / `subagent_spawn` / `session_end`。
- 存储于本地 `~/.feihong-code/sessions/<id>.log`（JSONL）。
- `fhcode resume <id>` 重放事件重建状态，从最后未完成的步骤续跑。

### 3.6 子代理隔离与并行

- 主代理分解任务 → 派发 N 个 `SubAgent`，每个在独立 `git worktree` 工作（互不污染工作副本）。
- 角色可配：`planner`（规划）/ `coder`（实现）/ `reviewer`（审查）。
- 合并阶段由 Orchestrator 协调冲突（基于文件归属/变更区间）。

### 3.7 技能系统

- 技能 = 预置 prompt 模板 + 工具组合 + 触发词。
- 内置：`/plan`、`/grill`、`/goal`；远期支持本地目录 + 团队共享插件。

### 5.4 Agent 编排器（节选）

```typescript
// src/agent/orchestrator.ts
export class Orchestrator {
  constructor(
    private readonly router: ModelRouter,
    private readonly tools: ToolRegistry,
    private readonly runtime: EventLog,
  ) {}

  async run(task: string): Promise<AgentResult> {
    this.runtime.append({ type: 'session_start', task });
    const plan = await this.planner.plan(task, this.router);
    const results = await Promise.all(
      plan.steps.map((s) => this.dispatchSubAgent(s)),  // 隔离 worktree 并行
    );
    return this.aggregate(results);
  }
}
```

### 5.5 模型路由（节选）

```typescript
// src/models/model-router.ts
export class ModelRouter {
  private providers: ModelProvider[] = [];
  register(p: ModelProvider) { this.providers.push(p); }
  async route(task: ModelTask): Promise<ModelProvider> {
    const scored = this.providers
      .filter((p) => task.capabilityTags.every((t) => p.tags.includes(t)))
      .sort((a, b) => this.score(a, task) - this.score(b, task)); // 按策略打分
    const pick = scored[0];
    if (!pick) throw new ModelError('无可用模型', 'router');
    return pick;
  }
}
```

### 5.6 工具实现示例（edit_file）

```typescript
// src/tools/file/edit-file.tool.ts
export const editFileTool: Tool = {
  name: 'edit_file',
  description: '按 old_string→new_string 精确替换文件内容',
  risk: 'safe',
  inputSchema: { type: 'object', properties: { path: { type: 'string' }, old_string: { type: 'string' }, new_string: { type: 'string' } }, required: ['path','old_string','new_string'] },
  async execute(input, ctx) {
    const before = await fs.readFile(input.path, 'utf8');
    if (!before.includes(input.old_string)) throw new ToolError('edit_file', 'old_string 未匹配');
    const after = before.replace(input.old_string, input.new_string);
    await fs.writeFile(input.path, after);
    ctx.runtime.recordDiff(input.path, before, after); // 可回滚
    return { ok: true, path: input.path };
  },
};
```

## 9. 安全与合规

遵循飞扬企源「管理给方案，技术给步骤，安全守底线」原则：

1. **命令沙箱**：`run_shell` 仅允许白名单命令；危险命令（rm -rf、:(){、curl|sh 等）强制拦截并需显式审批。
2. **数据不出域**：默认本地/私有部署；供应商密钥仅存于环境变量，绝不入库、不打印、不写日志。
3. **操作留痕**：所有模型调用、工具执行、文件变更进事件日志，可审计、可回滚。
4. **敏感信息脱敏**：日志自动遮蔽密钥/PII；客户信息、合同、财务等内部机密绝不进入 Agent 上下文。
5. **权限分级**：危险操作（删除、推送远端、修改系统配置）必须人工审批。
6. **绝不越权**：不修改薪酬/股权/制度、不承诺效果、不伪造身份。
