## 1. 产品安全定位

飞虹 Code 是**本地优先 / 可完全离线**的终端 AI 编程智能体，核心数据（对话、审计、经验库、知识库）默认落盘在用户本机（`~/.feihong-code`），**数据不出域**。这是面向政企私有化部署最核心的安全优势。

## 2. 架构与数据流

```
用户（终端/Web/VS Code扩展）
   │
   ├─▶ 认证（Token / SSO）→ RBAC 权限判定
   │
   ├─▶ Orchestrator（Agent 编排）
   │      ├─▶ 模型路由（OpenAI 兼容 / Ollama 本地 / 国内模型）
   │      ├─▶ 工具层（shell / 文件 / 浏览器 / 电脑控制）
   │      │     └─▶ 沙箱（read-only / workspace-write / container）
   │      └─▶ 变更审批（change-manager）→ 审计日志（audit）
   │
   └─▶ 数据存储：会话 / 经验 / 知识库 / 插件（本地，RBAC 保护）
```

## 3. 身份认证与访问控制

| 控制项 | 实现 |
|---|---|
| 认证 | Token 认证（`/api/auth/*`）；SSO 单点登录（`/api/sso/*`，未配置时明确返回状态） |
| 授权 | RBAC 角色：admin / developer / viewer 等，接口级权限判定 |
| 多租户 | 企业模式（`FH_ENTERPRISE=true`）下租户隔离（`FH_TENANT`） |
| 会话 | Web Token 校验；会话落盘管理（M3 会话命令） |
| 沙箱 | 三档：`read-only`（禁写禁执行）/ `workspace-write`（工作区内写，shell 受限）/ `container`（Docker 容器隔离，网络黑白名单） |

## 4. 数据保护与加密

| 数据 | 保护方式 |
|---|---|
| 配置 / API Key | 支持环境变量注入（`FH_*`）；禁止明文密钥提交（CI 密钥扫描强制） |
| 会话 / 经验 / 知识库 | 本地落盘，目录级权限；敏感字段脱敏（redact 工具） |
| 审计日志 | 追加式落盘（`fhcode audit`），覆盖命令执行与关键操作 |
| 网络 | 出站请求可配黑白名单（`FH_NETWORK_ALLOW/DENY`）；离线模式默认关闭出站 |

## 5. 供应链安全（v7.2.0 新增）

| 控制项 | 实现 |
|---|---|
| 依赖漏洞扫描 | CI `supplychain` job：`npm audit --audit-level=high`（强制）+ `osv-scanner`（OSV 全量库） |
| SBOM | CI 生成 CycloneDX SBOM（`sbom.cdx.json`，75 组件实测），随版本发布 |
| 密钥扫描 | CI 强制：发布包白名单（禁 .env/src/私钥）+ git 明文 API Key 扫描 |
| 依赖审计 | `npm audit --omit=dev` 生产依赖 high 及以上即失败 |

## 6. 合规基础（技术控制面）

- RBAC + 多租户：满足"最小权限 + 职责分离"要求
- 审计日志：满足"操作可追溯"要求
- 本地部署 + 数据不出域：满足"数据主权"要求
- 供应链（SBOM + 漏洞扫描）：满足"供应链安全"要求
- 认证状态：无第三方认证（SOC2/ISO27001），详见《合规认证准备清单》

## 7. 事故响应与安全更新

1. **上报**：GitHub Issues（模板：环境 / 复现 / 影响）
2. **响应**：核心维护者（飞扬企源研发中心）72 小时内响应
3. **修复**：安全补丁走独立 commit，回归冒烟后发布（`npm publish`）
4. **披露**：关键修复在 CHANGELOG 标注 `[security]`

## 8. 安全边界与声明（诚实）

- 沙箱 `container` 档依赖本机 Docker，未安装时自动降级提示（`fhcode doctor` 探测）
- 模型后端为第三方 API 时，提示词与代码会经网络传输至模型服务商（本地 Ollama 可完全避免）；请按政企要求选用本地模型
- 本白皮书描述**当前已实现**的技术控制面；认证类声明以第三方审计为准
