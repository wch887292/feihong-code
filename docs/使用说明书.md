## 一、快速开始

### 1.1 环境要求

- Node.js ≥ 18（推荐 20/22）
- npm ≥ 9
- git（diff/rollback/并行 worktree 需要）
- Docker（仅 `FH_SANDBOX_MODE=container` 时需要）
- 可选：Ollama（本地模型）、faster-whisper（本地语音）

### 1.2 安装

```bash
# 方式一：npm 全局安装（推荐）
npm install -g feihong-code
fhcode --version        # 应输出 7.6.0

# 方式二：源码构建
git clone https://github.com/wch887292/feihong-code.git
cd feihong-code
npm install
npm run build
node dist/cli/index.js --version   # 7.6.0

# 方式三：Electron 桌面版
npm run electron:build             # 生成 Windows 安装包

# 方式四：Android APK（versionCode 8 / 7.6.0）
# 从发布渠道安装，配套桌面端使用
```

### 1.3 首次配置

```bash
# 复制配置模板并填写模型 API Key
cp .env.example .env
# 编辑 .env：至少配置 FH_PROVIDERS 中一个 provider 的 apiKey

# 环境自检（可选）
fhcode doctor
```

### 1.4 第一个任务

```bash
# 直接下达自然语言任务
fhcode "给我写一个 Node.js 的 hello world HTTP 服务，监听 3000 端口"

# 查看会话与回滚
fhcode sessions          # 列出历史会话
fhcode diff <会话ID>     # 查看本次改动
fhcode rollback <会话ID> # 回滚改动
```

## 三、核心功能

### 3.1 对话编程

- 纯文本输出 + 实时思考过程展示
- 支持上下文压缩、检查点续跑（会话中途断线可 resume）
- 成本熔断：超预算自动止损（`FH_BUDGET_USD`）

### 3.2 代码补全（Web / VS Code）

- 多候选补全（按置信度 Top3）
- temperature 分层（quick 0 / full 0.3）
- 跨文件上下文（import 关联 + 工作区实时文档）
- 接受补全后自动 lint（语法错误实时波浪线提示）

### 3.3 全自动软件工程（SWE）

```bash
fhcode swe "给项目添加一个 markdown 转 HTML 的 CLI 工具"
```

流程：读取仓库结构 → 规划 → 实现 → 构建/测试验证 → 失败自动自愈重试 → 输出报告。验证支持测试（`--verifier test`）与文件级（`--verifier file`）两种模式。

### 3.4 SWE 评测（harness）

```bash
# 运行 mock 管道（无网络也可见证）
fhcode harness --split lite --limit 1 --mode mock --verifier file --report bench/run-xxx.md

# 使用官方测试验证器
fhcode harness --split lite --limit 1 --verifier test --test-command "npm run test"
```

差分语义：修复前确认用例原本失败 → 修复后 FAIL_TO_PASS 全过 → PASS_TO_PASS 回归不破坏既有功能。

### 3.5 团队协作

```bash
fhcode team "让两个 agent 分别实现前端和后端"
```

- 多 agent 消息总线协作
- 协作总览面板：任务状态漏斗 + 成员负载分布

### 3.6 自我迭代（统一经验库）

```bash
fhcode self-improve    # 查看学习沉淀（反思 + 经验库 + 成功率）
fhcode self-evolve status   # 运维视图：失败记录/技能/共享经验库
fhcode experiences     # 浏览经验库内容
```

- 失败、解决、技能沉淀自动写入共享经验库 `~/.feihong-code/experiences/experiences.jsonl`
- orchestrator 在后续任务自动检索注入经验，越用越强

### 3.7 语音编程

支持口头指令 → 编辑器/终端动作：新建/打开文件、复制/粘贴/剪切、替换、取消注释、切换终端/侧边栏/全屏、解释代码等。适合现场调试场景（如「打开终端」「上下反了」等口语化指令）。

## 四、配置

### 4.1 环境变量（.env）

| 变量 | 说明 | 默认 |
|------|------|------|
| `FH_HOME` | 数据目录 | `~/.feihong-code` |
| `FH_LOG_DIR` | 会话日志目录 | `~/.feihong-code/sessions` |
| `FH_PROVIDERS` | 模型供应商 JSON 数组（baseURL/apiKey/tags/costPer1k） | 空 |
| `FH_MODEL_STRATEGY` | 路由策略：cost / capability / latency | cost |
| `FH_BUDGET_USD` | 单任务预算上限（美元） | 0.5 |
| `FH_SANDBOX_MODE` | 沙箱模式：read-only / workspace-write / danger-full-access / container | workspace-write |
| `FH_SHELL_ALLOW` | Shell 白名单（逗号分隔） | git,npm,pnpm,node,ls,cat |
| `FH_REQUIRE_APPROVAL` | 危险操作是否需审批 | true |
| `FH_NETWORK_DENY` / `FH_NETWORK_ALLOW` | 网络域名黑白名单 | 空 |
| `FH_HOOKS` | hooks 配置（确定性控制） | 空 |
| `FH_MCP_SERVERS` | MCP 服务器配置 | 空 |

### 4.2 沙箱模式速查

| 模式 | 适用场景 |
|------|---------|
| `read-only` | 只读勘察、审计场景 |
| `workspace-write` | 默认；日常开发 |
| `danger-full-access` | 需要全权限的自动化脚本 |
| `container` | 执行不可信代码（Docker 断网隔离） |

## 五、常见问题（FAQ）

**Q1：`fhcode --version` 显示的不是 7.6.0？**
全局缓存旧包，先 `npm uninstall -g feihong-code` 再重装；源码方式先 `npm run build` 重新构建。

**Q2：没有模型 API Key 怎么办？**
使用 Ollama 本地模型（`FH_PROVIDERS` 配置 type 为 `ollama`），或使用内置 Mock 模式离线体验。

**Q3：任务执行到一半断了？**
`fhcode sessions` 找到会话 ID，`fhcode resume <id>` 续跑；checkpoint 会自动保存进度。

**Q4：改了文件想撤销？**
`fhcode diff <id>` 查看改动，`fhcode rollback <id>` 一键回滚（基于 git）。

**Q5：如何保证 AI 不乱改文件 / 不执行危险命令？**
默认 `workspace-write` 模式：仅工作区可写、Shell 白名单 + 审批；网络域名规则可拦截目标站点；`FH_REQUIRE_APPROVAL=true` 时危险操作需确认。

**Q6：经验库会不会无限膨胀？**
不会。统一经验库用稳定 id + upsert 合并：同一模式重复出现只累加 `sessionCount` 并更新成功率，不新增冗余条目。

**Q7：SWE 跑分准吗？**
诚实口径：自建任务集真实模型跑分 5/5 全过；mock 管道可离线复现；官方 SWE-bench（Python）受网络/环境限制尚未产出，详见 `docs/SWE_BENCH_REPORT.md`。

**更多故障排查**：见 `docs/常见问题与故障排查.md`、错误码 `docs/error-codes.md`。
