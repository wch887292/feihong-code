## 怎么读这个数（避免夸大/误读）
- 本仓（2000 文件）的改造前基线 `contextString.slice(0,2500)` 已自带 2500 字截断上限（约 647 tokens），所以「省 26%」是**在该上限下**的实测差值，并非「全仓裸喂 → brief」。
- brief 的真正价值不在省这点 token，而在**判别性**：legacy 是 contextString 的**头部切片**（对 2000 文件仓基本是目录树+语言分布的噪声），brief 是**按目标筛出的相关文件/符号/命令/红线**——信息密度更高。
- **可缩放下界**：仓库更大时，legacy 仍被 2500 字硬截断（丢目标相关信息），brief 体量有界（≤15 文件 + ≤20 符号），不会随仓膨胀。P0-A 单测已强制 brief ≤ 全量 contextString 的 20%。
> 结论口径：本项收益 = 「判别性 + 有界 + 小幅省 token」，主要治大会话吐空根因（不再整段塞全仓上下文），而非追求极致 token 数字。
