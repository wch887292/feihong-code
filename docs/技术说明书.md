## 一、产品概述

飞虹 Code（fhcode）是一款运行在终端/Web/IDE 三端的 AI 编程智能体，以「自然语言 → 代码闭环」为核心，支持多模型路由、企业级安全、全自动软件工程与自我迭代。零第三方运行时依赖（仅 express + zod），离线可用，可私有化部署。

**核心能力矩阵（v0.5.0）**：

| 领域 | 能力 |
|------|------|
| 编排 | ReAct 循环、规划器、上下文压缩、检查点续跑、成本熔断、自愈循环 |
| 模型 | 多模型路由（成本/能力/延迟策略 + fallback + 统计择优）、OpenAI 兼容 / Ollama / Mock |
| 工具 | 文件读写编辑、搜索、受管 shell、构建检查、测试运行、web 检索、技能加载 |
| 自我迭代 | 经验库（强化学习式 upsert/召回）、反思器回流、自愈闭环、eval 跑分、SWE-bench 基准 |
| 安全 | 沙箱四档、网络域名规则、hooks 确定性控制、RBAC、审计哈希链、配额熔断、脱敏、入站签名校验 |
| 生态 | SKILL.md 技能标准、Skills 市场（agentskills.io）、MCP、插件分发、Agent teams |
| 交付 | CLI/TUI、Web 控制台（任务面板）、VSCode 扩展、跨进程任务队列、消息渠道 |

## 三、核心模块详解

### 3.1 编排器（agent/orchestrator.ts）

ReAct 主循环 `run(goal, resume?)`，单次迭代：
1. `router.chat()` 调用模型（带能力标签路由）
2. 无工具调用 → 任务完成；有 → `executeToolRound()` 执行工具并回填 tool 消息
3. 错误检测：`roundErrors > 0` → `handleRecovery()`（分类 → 注入反思 → 重试，上限 `maxRetryErrors`）
4. 上下文压缩：`shouldCompact()` 触发时保留 system 指令（H4 修复）
5. 检查点落盘（`persist` 回调）+ 事件流（`onEvent`，P0-1 流式输出）

**事件流（P0-1）**：`OrchestratorEvent` 判别联合——model.response / tool.call / tool.result / self-heal / context.compact / session.end，CLI 流式渲染、TUI header 驱动、eval 计数复用同一事件源。

**成本熔断（M4）**：`cost >= maxCostUsd` 立即中止并提示 `resume` 续跑；`maxCostUsd=0` 不限。

**经验回流（M6）**：会话结束 `extractExperience()`（表驱动 EXTRACTORS）→ `upsertExperience`（稳定 id 合并、sessionCount 累积、成功率加权平均）；自愈成功额外固化 `extractFixPattern`。

### 3.2 模型路由（models/model-router.ts）

- 策略：`cost`（按 costPer1k）/ `latency`（本地优先）/ `capability`（标签加权）
- 择优：`rank(tags)` 能力过滤 + 历史成功率加权（≥3 次调用，最多 +0.3）
- fallback：按序尝试，失败记 `p.model`（修复：不产生空模型名条目），全部失败抛最后错误
- 统计：`updateStat()` 自动落盘（`statsHomeDir`，P5 闭环修复），`model-stats` 命令可查
- 子任务分工（P1-1）：`tags: ['code-gen','cheap']` 让低成本模型承担子任务

### 3.3 工具系统（tools/）

- `ToolRegistry`：注册/查找/执行，zod 校验入参，错误归一为 `ToolResult`
- 执行链顺序（纵深防御）：**沙箱 → PreToolUse hook → RBAC 守卫 → 工具 → PostToolUse/PostEdit hook**
- 沙箱四档（P0-2/P5-4）：`read-only` / `workspace-write` / `danger-full-access` / `container`（Docker 挂载工作区执行 shell）
- 网络域名规则：`FH_NETWORK_ALLOW/DENY` 对 run_shell 命令 URL 与 web 工具 URL 均生效
- hooks（P2-1）：`FH_HOOKS` JSON 数组，PreToolUse 非零退出拦截、PostEdit 编辑后触发，占位符 `{cwd}{tool}{path}{runId}{ok}`

### 3.4 SWE Agent（agent/swe-agent.ts + swe-planner + swe-verifier）

仓库读取（`repo-reader`，限流/忽略规则）→ 任务拆解（`planSweTask`）→ 逐任务「实现（runSubTask）+ 验证（构建/测试）+ 自愈重试」→ 报告。支持 `--plan-only` / `--verify-only` / `--max-tasks` / `--max-retries`。

**子代理（P3-4）**：`runSubAgent` 深度控制（默认 3 层），目标可拆解且未达上限时递归派生子代理（子目录隔离），逐层摘要回传（`summarizeSubTaskAnswer`，P2-2）。

### 3.5 Agent teams（agent/team.ts，P4-2）

- `TeamBus`：消息总线（send/receive/broadcast 定向与广播）
- `TaskBoard`：共享任务清单（claim 原子认领防重复，状态+owner 双校验）
- `runTeam`：多 agent 并发认领执行，`ok=false` 记 failed（修复），产出团队报告

### 3.6 企业安全（enterprise/）

| 模块 | 机制 |
|------|------|
| tenant | 租户隔离目录（`tenants/<id>/{sessions,audit,goals}`） |
| policy | RBAC：角色-工具矩阵（viewer/developer/operator/admin）+ denyShell 黑名单 + denyPaths 敏感路径，deny 优先 |
| audit | 哈希链（SHA-256，seq/prevHash 衔接），跨进程文件锁 + 指数退避，写入前脱敏，`audit verify` 校验 |
| quota | 租户日成本预算（`FH_TENANT_BUDGET_USD`），启动前 fail-fast 实时复核（M14 修复） |
| guard | 「策略→审批→审计」工具前置钩子，审计失败=拒绝 |

### 3.7 技能与市场（skills/）

- **SKILL.md 标准（P1-2）**：frontmatter（name/description）+ 正文；渐进式披露——索引（≤8KB）常驻 system prompt，正文由 `load_skill` 工具按需加载（Tier-2）
- 发现位置：仓库 `.agents/skills` / `.claude/skills` 逐级回溯 + 打包 `skills/` + 用户级 `~/.feihong-code/skills` + 插件技能目录
- **技能市场（P6）**：agentskills.io discovery 规范（`/.well-known/agent-skills/index.json`），`skill-market search/install/list`；RFC 3986 URL 解析、sha256 digest 校验、tar.gz 归档解包（零依赖手写，路径穿越防护）
- **插件（P3-3）**：`plugin.json` 打包 skills+hooks+MCP，用户级/项目级双级发现，`plugin install`（本地目录/git clone）

### 3.8 Web 与云执行（web/）

| 端点 | 说明 |
|------|------|
| `GET /api/health` | 公开健康检查（免鉴权） |
| `POST/GET /api/tasks`、`GET /api/tasks/:id` | 任务队列（Bearer 鉴权，P4-1） |
| `POST/GET /api/webhook` | webhook 调度入口注册/查询（P5-2） |
| `/api/...` 其它 | 需 `FH_WEB_TOKEN` Bearer（fail-closed，计时安全比较） |

**任务队列（P4-1/P6-4）**：状态机 queued→running→done|failed；并发上限（`FH_TASK_CONCURRENCY`）；跨进程持久化（`FH_TASK_PERSIST_DIR`，每任务一文件原子写，重启恢复：queued 重新入队、running 僵尸标记 failed）；webhook 状态回调（携带状态快照，修复 queued 丢失时序缺陷）。

**消息渠道（P5-6/O6）**：Telegram（`FH_CHANNEL_TELEGRAM_BOT_TOKEN`+`CHAT_ID`）与企业微信（`FH_CHANNEL_WECOM_KEY` 多 key）出站推送；出站白名单 `FH_CHANNEL_ALLOW`；入站签名校验工具 `verifyHmacSignature`（HMAC-SHA256 计时安全）/ `verifyWecomSignature`（企微 SHA1 排序）。

### 3.9 IDE 扩展（vscode-extension/）

薄壳设计（逻辑全在 CLI）：`fhcode.run`（选区上下文注入 `<selection>`）、`fhcode.review`（`review --json` → 编辑器内联诊断 DiagnosticCollection + CodeAction 建议）、`fhcode.diff`（原生 diff 编辑器 HEAD↔工作区，`fhcode-head` scheme）、`fhcode.output`；配置 `binaryPath` / `offline` / `reviewOnSave`。

| 协议 | 说明 |

## 五、安全设计

1. **纵深防御**：沙箱（技术边界）→ hooks（确定性控制）→ RBAC 策略（权限）→ 审计（留痕）→ 配额（成本）
2. **沙箱**：四档 + 网络域名规则（deny 全模式生效、allow 未命中即拦截）；`container` 档 Docker 隔离
3. **命令防护**：run_shell 注入元字符拦截（`[;&|`$(){}<>!]` 等）；受管命令（run_tests/build_check）仅允许包管理器脚本
4. **路径安全**：`safeJoin`（词法 + realpath 符号链接校验）；策略 denyPaths 敏感路径黑名单（.env/.git/config/密钥等）
5. **审计**：哈希链不可篡改（verifyAudit 检 seq/prevHash/hash 自洽）；写入前脱敏（SECRET_RE/Bearer/JWT/sk-）
6. **日志脱敏**：敏感 key 整值遮蔽 + 值形态（sk-/JWT/长令牌）遮蔽
7. **Web 鉴权**：Bearer token 计时安全比较（timingSafeEqual），fail-closed；body 限制 1MB
8. **入站安全**：webhook 签名校验（HMAC/企微），渠道白名单
9. **技能安全**：市场技能 digest 校验防投毒，tar.gz 路径穿越防护，SKILL.md 强制 name frontmatter
