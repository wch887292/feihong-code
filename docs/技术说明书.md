## 1. 概述与定位

飞虹 Code（命令名 `fhcode`）是终端 AI 编程智能体，以"目标"为入口，自动完成需求解析 → 规划 → 工具调用 → 反思的闭环，并支持多子代理并行、会话恢复审计，以及企业级权限/审计/多租户/成本治理。

- **适用场景**：代码生成与修改、批量重构、离线脚本化任务、企业内多团队共享的智能体底座。
- **能力边界**：不修改薪酬/股权/制度、不承诺效果、不伪造身份；危险操作一律人工审批或拒绝。
- **两种形态**：
  - **社区版（默认）**：CLI 闭环 + 并行 + 恢复审计。
  - **企业版（注入 guard 或 `FH_ENTERPRISE!=='false'`）**：在 community 之上叠加 RBAC、防篡改审计、多租户隔离、成本治理、Web 控制台。未注入 guard 时行为同社区版（无感降级）。

## 2. 系统架构

### 2.1 分层架构

```
cli         命令解析 / 分发 / 交互入口（含 serve）
  └─ agent  编排层（Orchestrator / 并行 / Planner / SubAgent）
       └─ tools       工具集（file / search / shell / verify）+ 注册表 + 守卫接口
            └─ runtime    会话持久化 / git diff·rollback / 成本计量
                 └─ models      模型提供商适配 + 成本估算
                      └─ shared     通用工具（日志/脱敏/错误）
  enterprise  企业能力（tenant/policy/audit/quota/guard/index）—— 可选注入
  skills      技能定义（plan/grill/goal 等）
  web         Web 控制台（server/auth/public）—— M5 BETA
```

### 2.2 执行流（社区版 vs 企业版）

- **社区版**：`cli` → `Orchestrator.run(goal)` → 循环「规划→选工具→`tool.registry.execute`→反思」→ 终态答案。
- **企业版**：在「选工具 → 执行」之间插入**唯一权威闸门 `guard`**：
  1. `guard.check(tool, args)` 调 `policy.evaluate` 做策略判定；
  2. 命中审批项且无审批通道 → 拒绝；有通道 → 询问并记录 approved/rejected；
  3. 审计留痕（allow/deny/approval）；审计写入失败 = 拒绝执行；
  4. 通过后才进入 `tool.registry.execute`，且注入 `security` 置空以避免工具层二次弹审批（去重）。

| 目录 | 职责 |

| `src/cli` | 命令解析（`commands.ts`）、分发（`index.ts`）、业务编排（`run.ts`）、版本与署名（`version.ts`） |

## 3. 企业级能力技术细节（M4）

### 3.1 RBAC 与策略引擎（`policy.ts`）

**判定顺序（deny 优先）**：

1. `run_shell` 命中**危险命令黑名单** → `deny`（无论角色）。
2. 命中**敏感路径黑名单**或**沙箱越界** → `deny`（admin 也拦）。
3. 角色矩阵：`deny` / `approval`（需人工审批）/ `allow`。
4. `run_shell` 命中**白名单** → 免审批 `allow`。

**角色矩阵（`DEFAULT_POLICY.roles`）**：

| 角色 | 允许工具 | 危险命令 | 单任务预算上限 |
|------|----------|----------|----------------|
| `viewer` | read / list / grep | — | $0.1 |
| `developer` | + write / edit / tests / build | 需审批 | $1 |
| `operator` | 全部 | 需审批 | $5 |
| `admin` | 全部 | 需审批 | ∞ |

**危险命令黑名单（23 条，`denyShell`）**：
`rm -rf /`、`rm -rf ~`、`rm -rf *`、`mkfs`、`dd if=`、`fork bomb :(){`、`shutdown`、`reboot`、`halt`、`format `、`del /s`、`rd /s`、`chmod 777 /`、`chown -R root`、`curl | sh`、`curl|sh`、`wget | sh`、`wget|sh`、`iptables -F`、`net user`、`reg delete`、`history -c`、`shred `。

**敏感路径黑名单（11 类，`denyPaths`）**：
`.env`、`.git/config`、`.git/hooks`、`.npmrc`、`.ssh`、`id_rsa`、`id_ed25519`、`credentials`、`.aws`、`.kube/config`、`shadow`。

**策略覆盖规则（仅加严）**：
- 加载优先级：`DEFAULT_POLICY` → `<FH_HOME>/policy.json` → `<租户>/policy.json` → 环境变量 `FH_POLICY`（JSON 片段）。
- 合并（`mergePolicy`）：**黑名单取并集**（不能放宽）；角色预算只能调低或持平；新增 deny 规则有效，移除 deny 无效。
- 即：任何层级的覆盖只能让策略更严格，不能削弱内置安全基线。

### 3.2 防篡改审计（`audit.ts`）

**哈希链结构**：每条记录 `AuditRecord` 含 `seq`、`ts`、`tenant`、`user`、`role`、`runId`、`action`、`resource`、`decision`、`reason`、`prevHash`、`hash`。
- `computeHash(r) = sha256([seq, ts, tenant, user, role, runId, action, resource, decision, reason, prevHash].join('|'))`
- 创世哈希 `GENESIS = '0'.repeat(64)`（首条 `prevHash`）。
- **按月切分**：`audit-YYYY-MM.jsonl`，每条一行 JSON，同步 `appendFileSync` 追加；写入失败抛错（上层拒绝执行）。

**脱敏（`redact`）**：值中出现 `apiKey=`/`secret=`/`token=`/`password=`/`Authorization: Bearer`/`sk-*` 等一律替换为 `***`，写入前即脱敏。

**校验（`verifyAudit`）**：
- 检查 `seq` 连续、`prevHash` 与上一行 `hash` 衔接、`hash` 自洽（重算一致）；
- 任一断点返回 `{ ok:false, brokenAt: <行号> }` 定位篡改位置。

### 3.3 多租户隔离（`tenant.ts`）

**物理目录隔离**：`<FH_HOME>/tenants/<tenantId>/{sessions,audit,goals}`。
- 租户 ID 校验：`ID_RE = /^[A-Za-z0-9._-]{1,64}$/`，防路径穿越。
- **默认租户兼容**：`FH_TENANT` 缺省且尚未建 `tenants/default` 但存在旧 `<FH_HOME>/sessions` 时，沿用旧目录（平滑升级，不丢历史）。
- 用量统计（`listTenants`）：仅提取 `costUsd`/`updatedAt`，不反序列化整份对话。

### 3.4 成本治理（`quota.ts`）

- **单任务熔断**：`Orchestrator` 循环内 `if (maxCost>0 && cost>=maxCost)` 终止并给出终态答案（告警式，不抛错）。
- **租户日预算 fail-fast**：任务启动前 `assertQuota()` 调 `checkQuota()`；超限抛 `QUOTA_EXCEEDED`（HTTP 429 语义）并审计 `quota:block`。
- 日预算解析优先级：`FH_TENANT_BUDGET_USD` > 策略 `tenantDailyBudgetUsd`；缺省为 0（不限制）。
- 当日统计：正则提取 `updatedAt` 前缀匹配当天 UTC。

## 4. 数据契约与格式

### 4.1 AuditRecord（审计记录）

```json
{
  "seq": 1,
  "ts": "2026-08-10T14:30:00.000Z",
  "tenant": "acme",
  "user": "alice",
  "role": "developer",
  "runId": "run_xxx",
  "action": "tool:write_file",
  "resource": "src/app.ts",
  "decision": "allow",
  "reason": "命中角色矩阵 allow",
  "prevHash": "0000...0000",
  "hash": "a1b2...ff"
}
```

### 4.2 Policy（策略片段，可经 FH_POLICY / policy.json 覆盖）

```json
{
  "roles": { "viewer": { "allow": ["read","list","grep"], "maxCostUsd": 0.1 } },
  "denyShell": ["rm -rf /"],
  "denyPaths": [".env"],
  "tenantDailyBudgetUsd": 0
}
```

### 4.3 TenantContext

```ts
interface TenantContext {
  tenant: string;      // 校验后的租户 ID
  user: string;        // FH_USER 或 'default'
  role: Role;          // viewer|developer|operator|admin
  home: string;        // FH_HOME
  dirs: { sessions: string; audit: string; goals: string };
}
```

### 4.4 配置变量全集

| 变量 | 作用 | 默认 |
|------|------|------|
| `FH_HOME` | 数据根目录（会话/审计/租户） | 平台默认（如 `~/.fhcode`） |
| `FH_ENTERPRISE` | 企业模式开关（`false` 关闭） | 开启（注入 guard 时） |
| `FH_TENANT` / `FH_USER` / `FH_ROLE` | 租户/用户/角色身份 | `default`/`default`/`developer` |
| `FH_TENANT_BUDGET_USD` | 租户日预算（优先于策略） | 0（不限制） |
| `FH_POLICY` | 策略 JSON 片段（覆盖） | 空 |
| `FH_WEB_PORT` / `FH_WEB_TOKEN` | Web 控制台端口/令牌 | `8080` / 空（禁用） |
| `FH_OFFLINE` | 强制离线（不请求模型） | 未设 |
| `FH_REQUIRE_APPROVAL` | 危险操作是否需审批 | `true` |
| `FH_BUDGET_USD` | 单任务成本告警阈值 | 未设 |

## 6. 部署架构

### 6.1 CI 四流水线（`.github/workflows/ci.yml`，零 Secrets 全离线）

1. **build**：Node 18/20/22 矩阵 + 类型检查 + 编译 + 离线端到端闭环 + `/plan` `/grill` 只读技能。
2. **enterprise**：`verify-m4.mjs`（41 项全离线断言：RBAC/审计链/多租户/配额）+ CLI 企业命令冒烟 + **租户隔离断言**（beta 不得读到其他租户会话）。
3. **security**：`npm pack --dry-run` 白名单校验（禁 `.env`/`src`/`.workbuddy`/`policy.json`/`id_rsa`）+ 仓库明文密钥扫描 + `npm audit`。
4. **docker**：构建镜像（不推送）+ 容器内 `whoami` 冒烟 + Web 控制台 `/api/health` 健康检查（HTTP 200）。

### 6.2 Docker 部署（稳定部署推荐）

- **镜像**：多阶段 `Dockerfile`，构建阶段编译 `dist`，运行阶段仅 `express`+`zod` 生产依赖。
- **数据卷**：`FH_HOME=/data/fhcode` 挂载命名卷，持久化会话/审计/租户。
- **端口**：默认 `8080`（Web 控制台）。
- **编排**：`docker-compose.yml` 提供一键 `docker compose up -d`，令牌经 `FH_WEB_TOKEN` 环境变量注入。
- **反向代理建议**：前置 Nginx/Caddy 做 TLS 终止与限流；`FH_WEB_TOKEN` 务必为强随机值，勿用默认值。

### 6.3 安装方式

- npm 全局：`npm install -g feihong-code`（bin=`fhcode`）。
- 源码：`git clone` → `npm install` → `npm run build` → `node dist/cli/index.js`。
- Docker：`docker build -t feihong-code .` → `docker run -p 8080:8080 feihong-code serve`。
- 安装脚本：`./install.sh`（封装 npm 全局安装）。

## 7. 安全模型

- **密钥**：仅存 gitignored `.env`；CLI 不回显完整 key；日志脱敏（`redact`）。
- **最小权限**：`guard` 为唯一权威闸门，deny 优先；Web 仅观测不执行，保持 guard 权威。
- **fail-closed**：Web 无令牌/错令牌 → 401；审批通道缺失 → 拒绝；审计写入失败 → 拒绝。
- **发布包白名单**：`package.json` 的 `files`（仅 `dist`+元数据+`docs`）+ `.npmignore`（排除 `.env`/`src`/`.workbuddy`/脚本/日志）双重保障，`.env` 等绝不随 `npm publish` 泄露。

## 8. 构建与验证

| 脚本 | 作用 |
|------|------|
| `npm run typecheck` | `tsc --noEmit` 类型检查 |
| `npm run build` | `tsc` 编译 + 拷贝 Web 静态资源到 `dist/web/public` |
| `npm run verify:m4` | 41 项企业能力离线断言 |
| `npm run verify` | typecheck + build + verify:m4 串联 |

> **本地构建注意**：Windows 本地 `tsc` 编译可能被 Windows Defender 实时扫描短暂锁文件（表现为 emit 退出 1 或后台挂起），属环境限制非代码缺陷；GitHub Actions（windows/ubuntu runner）无此问题。CI 是权威构建来源。

**verify-m4 断言覆盖（41/41）**：RBAC 矩阵(5) / deny 优先(4) / 策略覆盖加严(4) / 审计哈希链(7) / 守卫链路(11) / 多租户(7) / 配额(3)。
