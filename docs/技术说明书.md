## 一、产品概述

飞虹 Code（fhcode）是一款运行在 **CLI / Web / Electron 桌面 / Android APK / VS Code** 五端的 AI 编程智能体，以「自然语言 → 代码闭环」为核心，覆盖对话编程、代码补全、全自动软件工程（SWE）、团队协作与自我迭代。零第三方运行时依赖（仅 express + zod），支持离线私有化部署与企业级安全治理。

**核心能力矩阵（v7.6.0）**：

| 领域 | 能力 |
|------|------|
| 编排 | ReAct 循环、规划器（planner）、并行 orchestrator、检查点续跑、成本熔断、自愈循环、多 agent 团队协作 |
| 模型 | 多模型路由（成本/能力/延迟策略 + fallback + 统计择优）、OpenAI 兼容 / Ollama / Mock、成本记账 |
| 工具 | 文件读写编辑、搜索、受管 shell、构建检查、测试运行、web 检索、技能（SKILL.md）加载、MCP 服务 |
| 代码智能 | 补全引擎（多候选 Top3 + temperature 分层）、LSP 语义诊断、代码 RAG、符号索引、类型检查、质量门禁 |
| 软件工程 | SWE Agent（读取→规划→实现→验证→自愈重试）、SWE-bench harness（差分语义校验）、git 集成（diff/rollback/worktree） |
| 自我迭代 | 统一经验库（self-evolve + self-improve 收敛）、反思回流、自愈闭环、eval 跑分 |
| 语音 | voice-programming：语音/口头指令 → 编辑器/终端命令（自然语言 → 结构化动作） |
| 安全 | 沙箱四档、网络域名规则、hooks 确定性控制、RBAC、审计哈希链、配额熔断、脱敏、入站签名校验、SBOM |
| 生态 | SKILL.md 技能标准、技能市场（本地种子源）、插件分发、MCP、Agent teams |
| 交付 | CLI/TUI、Web 控制台（任务面板/监控）、Electron 桌面、Android APK、VS Code 扩展、跨进程任务队列 |

## 二、总体架构

```
┌──────────────────────────────────────────────────────────────────┐
│                          接入层 delivery                           │
│   CLI(index/run/repl/tui) · Web(server/task-queue) · Electron     │
│   Android(Capacitor H5) · VS Code 扩展 · 语音(voice-programming)   │
└───────────────────────────────┬──────────────────────────────────┘
                                 │
┌───────────────────────────────▼──────────────────────────────────┐
│                       编排层 agent/                               │
│   Orchestrator(ReAct) · parallel-orchestrator · planner           │
│   repo-reader · swe-agent · swe-planner · swe-verifier            │
│   subagent(嵌套) · custom-agent · solo-agent · event-driven       │
│   team / multi-agent / team-collaboration(协作可视化)              │
│   self-heal · self-correction · quality-gate · code-writer        │
│   completion-engine · code-rag · symbol-index · repo-context      │
│   experience(统一经验库) · self-improver · layered-memory          │
└───────────────────────────────┬──────────────────────────────────┘
                                 │
┌───────────────────────────────▼──────────────────────────────────┐
│                        工具层 tools/                              │
│   文件读写编辑 · 受管 shell(sandbox) · 构建检查 · 测试运行          │
│   web 检索 · 技能加载 · MCP · 代码审查 · 类型检查                  │
└───────────────────────────────┬──────────────────────────────────┘
                                 │
┌───────────────────────────────▼──────────────────────────────────┐
│                        模型层 models/                             │
│   model-router(成本/能力/延迟策略) · provider 适配 · cost 记账      │
│   OpenAI 兼容 / Ollama / Mock                                    │
└───────────────────────────────┬──────────────────────────────────┘
                                 │
┌───────────────────────────────▼──────────────────────────────────┐
│       安全/治理/支撑层  shared · runtime · enterprise · harness   │
│   沙箱四档 · 网络规则 · hooks · RBAC · 审计链 · 配额熔断 · 脱敏     │
│   会话持久化 · 事件日志 · 配置中心 · 错误码 · SWE harness          │
└──────────────────────────────────────────────────────────────────┘
```

**分层职责**：
- **接入层**：把 CLI 参数、HTTP 请求、IDE 事件、语音输入统一归一化为「任务目标 + 上下文」，经 `executeTask / runSwe / runTeam` 等入口进入编排层。
- **编排层**：核心大脑。`orchestrator` 跑 ReAct 循环（思考→工具→观察），`swe-agent` 跑「读取仓库→规划→实现→验证→自愈重试」的软件工程闭环，`team` 支持多 agent 消息总线协作。
- **工具层**：把文件/shell/网络/搜索能力封装为统一 Tool 接口，全部经过 `sandbox`（权限/网络/白名单）拦截。
- **模型层**：多供应商路由，按成本/能力/延迟策略选模型，失败自动 fallback，全程成本记账。
- **支撑层**：安全治理（RBAC/审计/配额）、运行时（会话/事件日志/持久化）、评测（SWE harness）。

## 三、模块设计

| 模块 | 职责 |
|------|------|
| `orchestrator.ts` | ReAct 主循环：规划、工具调用、观察整合、上下文压缩、检查点续跑、成本熔断 |

| `repo-reader.ts` | 仓库预读：结构、入口、依赖、配置提取 |

| `swe-planner.ts` | SWE 子任务规划与拆解 |
| `swe-verifier.ts` | SWE 结果验证（测试/构建/静态检查） |

| `type-checker.ts` / `lint.ts` / `code-review.ts` | 静态质量校验 |

### 3.2 SWE 评测（src/harness/）

SWE-bench 语义评测管道，四段式：

```
loader.ts     → 加载任务（problem_statement / FAIL_TO_PASS / PASS_TO_PASS）
executor.ts   → 在沙箱中 checkout 仓库并执行测试命令
verifier.ts   → 三段式差分校验：
                 ① beforeCommand：修复前确认 FAIL_TO_PASS 原本失败（防假阳性）
                 ② 修复后 FAIL_TO_PASS 全部通过（问题确实被修复）
                 ③ PASS_TO_PASS 回归通过（未修坏既有功能）
reporter.ts   → 输出可复现的跑分报告（markdown/json）
```

- `types.ts` 定义任务与结果类型；`harness.ts` 编排管道；`index.ts` 导出入口。
- `verifier.ts` 对测试 id 做 shell 安全转义（`quoteTestId`），受管命令白名单 `sanitizeManagedCommand` 只放行 `npm/pnpm/yarn/bun`，杜绝注入。
- 跑分现状：自建任务集真实模型跑分 5/5 全过；mock 管道 1/1 通过（`bench/run-2026-08-28-mock.md`，诚实标注口径）。官方 SWE-bench（Python/pytest）受限于 HF 网络不可达与 Docker 环境，见 `docs/SWE_BENCH_REPORT.md`。

### 3.3 语音编程（src/voice/voice-programming.ts）

把自然语言口头指令转译为编辑器/终端动作：

- 命令类型：`new_file`、`open_file`、`edit`、`copy`、`paste`、`cut`、`close_file`、`replace`、`uncomment`、`stop_code`、`toggle_terminal`、`toggle_sidebar`、`toggle_fullscreen`、`explain_code`、`switch_file` 等。
- 规则匹配：正则 + 置信度排序；等置信度时**数组顺序即优先级**（语义更具体的规则前置，避免「打开终端」被 `open_file` 抢占）。
- 随 v7.6.0 补齐死类型规则（copy/paste/cut/close_file/replace/uncomment）、修复 `new_file`「创建一个叫 X 的文件」识别、`explain_code` 放宽「解释」，并新增 7 项单元测试。

### 3.4 自我迭代（src/self-evolve/ + src/agent/experience.ts）

**v7.6.0 关键设计：双系统收敛为单一经验库。**

| 系统 | 职责 | 数据 |
|------|------|------|
| self-evolve（旧式，运维视图） | 失败记录、技能沉淀、每日复盘报告 | `~/.feihong-code/self-evolve/{failures,skills-index,history}.json` |
| self-improve（新式，学习闭环） | 任务反思 → 经验回流 → orchestrator 检索注入 | `~/.feihong-code/experiences/experiences.jsonl` |

**收敛机制**（`src/self-evolve/manager.js`）：
- `recordFailure` → 写入 `error-pattern` 经验（含错误类型/任务描述/规避建议）
- `markResolved` → 写入 `success-pattern` 经验（含解决方案）
- `createSkill` → 写入 `success-pattern` 经验（含技能名/触发词/方案）
- 经验 id 由 `shortHash(type:key)`（djb2 变体，base36）生成，与 `experience.ts` 算法一致，保证跨系统 id 对齐；upsert 语义（同 id 合并 sessionCount、加权成功率、标签合并、刷新 lastUsedAt）防膨胀。

**检索**（`experience.ts`）：`retrieveRelevantExperiences` 加权打分（标签重叠×3 + 成功率×2 + 子串 +2 + token×0.5 + 新鲜度衰减），`generateExperiencePrompt` 分组注入（成功模式优先/失败模式警示）。

### 3.5 模型路由（src/models/）

- `model-router.ts`：按策略（cost 成本 / capability 能力 / latency 延迟）选模型；失败 fallback；按标签过滤（code-gen/cheap/local/long-context）。
- `cost.ts`：每 1k token 成本记账，支持单任务预算熔断（`FH_BUDGET_USD`）。
- provider 支持：OpenAI 兼容（DeepSeek/通义 Qwen 等）、Ollama 本地、Mock（离线演示）。

### 3.6 工具层与沙箱（src/tools/）

统一 `Tool` 接口（`tool.interface.ts`）+ 注册表（`tool.registry.ts`）：

- 文件：读写/编辑（`safe-path.ts` 路径安全校验）
- Shell：受管执行，`sandbox.ts` 四档模式拦截
- 网络：域名规则（`FH_NETWORK_DENY/ALLOW`）
- 搜索/检索：web 检索、代码 RAG

**沙箱四档**（Codex 对齐）：

| 模式 | 写限制 | Shell | 网络 |
|------|--------|-------|------|
| `read-only` | 禁止 | 只读勘察 | 按规则 |
| `workspace-write`（默认） | 仅工作区 | 白名单 + 审批 | 按规则 |
| `danger-full-access` | 放开 | 白名单（危险命令黑名单仍生效） | 按规则 |
| `container` | Docker 隔离 | `--network none` + 内存/pids 上限 + `--cap-drop ALL` + `no-new-privileges` | 断网 |

### 3.7 安全与治理（src/enterprise/ + src/shared/ + src/runtime/）

- **RBAC**：`whoami` / `policy` 命令，角色与权限策略
- **审计**：`audit` 命令，审计哈希链（篡改可检测），`audit --verify` 校验
- **多租户**：`tenants` 命令
- **hooks**：确定性控制（`FH_HOOKS`），事前/事后回调
- **脱敏**：日志与输出的敏感信息脱敏
- **配额熔断**：成本/时长/轮次限额
- **入站签名校验**：Web 控制台请求验签
- **SBOM**：`npm run security`（npm audit + CycloneDX SBOM + osv-scanner 可选）
- **错误码**：统一错误分类（`docs/error-codes.md`）

## 四、数据设计

### 4.1 数据目录（`~/.feihong-code/`，可用 `FH_HOME` 覆盖）

```
~/.feihong-code/
├── config/                 # 配置
├── sessions/               # 会话持久化 + 事件日志（FH_LOG_DIR）
├── self-evolve/            # 失败记录/技能索引/历史/每日复盘报告（运维视图）
├── skills/                 # 用户技能（SKILL.md）
├── experiences/
│   └── experiences.jsonl   # ★ 统一经验库（self-evolve + self-improve 共用）
├── bench/                  # SWE 跑分缓存与报告
└── ...
```

### 4.2 统一经验库 schema（experiences.jsonl，每行一条）

```jsonc
{
  "id": "exp-<base36 shortHash(type:key)>",   // 稳定 id，跨 run 合并
  "type": "success-pattern",                   // success-pattern | error-pattern | path-planning | tool-efficiency | performance-tip
  "key": "fix:compile-error",
  "title": "自愈修复经验: compile-error",
  "content": "…具体方案与建议…",
  "tags": ["compile-error", "self-heal", "fix", "success"],
  "metadata": {
    "sessionCount": 2,          // 出现次数（同 id 累加）
    "successRate": 0.85,        // 加权成功率
    "createdAt": "ISO 时间",
    "lastUsedAt": "ISO 时间"
  }
}
```

### 4.3 会话与事件

- 每次运行生成 `runId`（UUID），`EventLog` 记录全量事件，`SessionStore` 持久化会话；支持 `sessions` 列出、`resume` 续跑、`diff` 查看变更、`rollback` 回滚。

## 五、接口设计

### 5.1 CLI 命令（`fhcode <command>`）

| 命令 | 说明 |
|------|------|
| `fhcode <goal>` | 直接执行自然语言任务（默认入口） |

| `whoami` / `policy` | RBAC 身份与策略 |
| `audit [--verify]` / `tenants` | 审计（哈希链校验）/ 多租户 |
| `doctor` | 环境自检 |
| `tui` | 多面板终端 UI |
| `serve [port]` | 启动 Web 控制台 |
| `plugin` / `skill-market` / `skill-new` | 插件与技能管理 |
| `review <path>` | 代码审查 |
| `team <goal>` | 多 agent 团队协作 |
| `code-write <goal>` / `quality-gate <path>` | 代码生成与质量门禁 |
| `self-improve` / `self-evolve <action>` | 自我迭代（统一经验库） |
| `model-stats` / `experiences` | 模型用量统计 / 经验库浏览 |
| `harness` / `swe <goal>` | SWE 评测与软件工程执行 |
| `/plan` `/grill` `/self-heal` | 内置技能（规划/拷问/自愈） |

### 5.2 HTTP API（`fhcode serve`）

- `/api/health`：健康检查（返回版本号）
- `/api/task` 等任务面板接口：Web 控制台任务下发与状态查询
- `/api/lint`：补全接受后轻量语法校验
- 入站请求签名校验；CORS/权限控制

### 5.3 LSP / 编辑器协议

- Monaco 语义诊断：编辑时 LSP 诊断波浪线 + hover 详情
- VS Code 扩展：补全、跨文件上下文、accept 后 lint

### 5.4 语音输入

- `voice-programming`：语音识别文本 → 命令规则匹配 → 结构化动作（open/edit/toggle/explain 等）
