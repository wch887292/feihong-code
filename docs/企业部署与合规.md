# 飞虹 Code — 企业部署与合规指南（M4）

> 晋江市飞虹智科技企业管理有限公司 · 飞扬企源研发中心 · 负责人：吴赐虹

本文面向**企业管理员 / 平台工程 / 安全合规**角色，说明如何把飞虹 Code 以受控方式部署到团队、部门乃至多客户（多租户）环境中。

---

## 一、能力总览

| 维度 | 能力 | 关键命令 |
| --- | --- | --- |
| 身份 | 租户 / 用户 / 角色由环境注入，容器与网关友好 | `fhcode whoami` |
| 权限 | RBAC 角色矩阵 + deny 优先黑名单 + 沙箱越界拦截 | `fhcode policy` |
| 审计 | sha256 哈希链、脱敏、按月切分、可验证 | `fhcode audit` / `fhcode audit verify` |
| 隔离 | 会话 / 审计 / 目标物理分目录 | `fhcode tenants` |
| 成本 | 单任务熔断 + 租户日预算 fail-fast | `FH_TENANT_BUDGET_USD` |
| 交付 | 三条全离线 CI 流水线 + 发布包白名单 | `npm run verify` |

企业模式默认开启。若需退回社区版行为（无租户、无审计链、无 RBAC）：`FH_ENTERPRISE=false`。

## 二、身份模型

```bash
export FH_TENANT=acme          # 租户 ID：^[A-Za-z0-9._-]{1,64}$
export FH_USER=wuchihong       # 用户标识，写入审计 actor
export FH_ROLE=developer       # viewer | developer | operator | admin
```

- 三者均可由**容器编排 / SSO 网关 / CI Runner** 注入，CLI 自身不做认证——认证是上游职责，飞虹 Code 只负责**授权与留痕**。
- `FH_TENANT` 非法（含 `../`、超长、特殊字符）时启动即报 `TENANT_ID_INVALID`，杜绝路径穿越。
- `FH_ROLE` 非法值直接报 `ROLE_INVALID`，不做"降级容错"——权限问题不允许猜。

### 推荐角色分配

| 场景 | 角色 | 理由 |
| --- | --- | --- |
| 代码审查 / 只读排障 | `viewer` | 仅能读取与检索，任何写入都被拒 |
| 日常研发 | `developer` | 可写代码与跑测试，shell 需审批 |
| 值班 / 运维处置 | `operator` | 全工具可用，shell 仍需审批，成本上限 $5 |
| 平台管理员 | `admin` | 无成本上限，但**危险命令与敏感路径依旧拒绝** |

## 三、权限策略

### 3.1 判定顺序（deny 优先）

```
1) 危险 shell 命令黑名单   → deny（admin 也拦）
2) 敏感路径黑名单          → deny
3) 沙箱越界（逃出 cwd）    → deny
4) 角色-工具矩阵           → deny / approval / allow
5) shell 白名单            → allow（否则 approval）
```

前三条是**硬底线**，不受角色影响，也不能被人工审批放行——批准了也不执行。

### 3.2 内置黑名单

- **危险命令（23 条）**：`rm -rf /`、`rm -rf ~`、`mkfs`、`dd if=`、fork 炸弹 `:(){`、`shutdown`、`reboot`、`format `、`del /s`、`rd /s`、`chown -R root`、`curl | sh`、`wget | sh`、`iptables -F`、`reg delete`、`history -c`、`shred ` 等。
- **敏感路径（11 类）**：`.env`、`.git/config`、`.git/hooks`、`.npmrc`、`.ssh`、`id_rsa`、`id_ed25519`、`credentials`、`.aws`、`.kube/config`、`shadow`。

### 3.3 策略覆盖（只能加严）

优先级从低到高：

```
DEFAULT_POLICY
  → <FH_HOME>/policy.json                 全局策略
  → <FH_HOME>/tenants/<租户>/policy.json  租户策略
  → FH_POLICY 内联 JSON                    临时覆盖（CI / 调试）
```

**黑名单取并集**——下级配置只能新增禁止项，无法删除上级的禁止项。这条设计确保"租户自定义策略"永远不能成为提权通道。

`policy.json` 示例：

```json
{
  "roles": {
    "developer": { "maxCostUsd": 0.25, "approvalTools": ["run_shell", "write_file"] }
  },
  "denyShell": ["npm publish", "docker push", "kubectl delete"],
  "denyPaths": ["config/secrets", "deploy/prod"],
  "tenantDailyBudgetUsd": 20
}
```

### 3.4 审批通道

| 环境 | 行为 |
| --- | --- |
| TTY 交互终端 | 逐条弹出 `y/n`，用户显式批准才执行 |
| 非交互（CI / 管道 / 守护进程） | 回退白名单审批器：命中 `FH_SHELL_ALLOW` 自动通过，其余拒绝并留痕 |

> **守卫是唯一权威闸门**：策略判定、审批、审计在工具执行前一次性完成，工具层不会二次弹审批，杜绝重复询问与决策打架。

## 四、审计与取证

### 4.1 存储

```
<FH_HOME>/tenants/<租户>/audit/audit-YYYY-MM.jsonl
```

append-only、按月切分、同步写入（不缓冲，进程崩溃不丢记录）。

### 4.2 记录结构

```json
{
  "seq": 2,
  "ts": "2026-08-10T06:41:43.118Z",
  "tenantId": "acme",
  "userId": "wuchihong",
  "role": "developer",
  "runId": "2d1e3188-...",
  "action": "tool:write_file",
  "resource": "demo-output.txt",
  "decision": "allow",
  "reason": "rbac.allow — 角色 developer 允许调用 write_file",
  "prevHash": "…",
  "hash": "…"
}
```

`decision` 取值：`allow` / `deny` / `approved`（人工批准）/ `rejected`（人工拒绝或无审批通道）/ `info`（会话起止等）。

覆盖动作：`session:start`、`session:end`、`session:rollback`、`skill:goal`、`quota:block`、`tool:<工具名>`。

### 4.3 防篡改验证

```bash
fhcode audit verify
```

链式校验三件事：**seq 连续**（防删除/插入）、**prevHash 衔接**（防重排）、**hash 自洽**（防内容改写）。任一失败会定位到具体条目：

```
❌ 审计链校验失败：共 5 条，断点在第 3 条
   记录内容被篡改：hash 不自洽（期望 8b3a6990664e…）
```

退出码为 `2`，可直接接入监控告警：

```bash
fhcode audit verify || alertmanager-cli fire --name fhcode-audit-tampered
```

### 4.4 脱敏

`resource` / `reason` 写入前统一脱敏：`apiKey=` / `secret=` / `token=` / `password=` / `Authorization: Bearer` 的值替换为 `***`，`sk-xxxxx` 形态密钥替换为 `sk-***`。**审计日志本身不会成为泄密源**。

> 合规提示：审计目录建议单独挂载只读快照卷或定期归档至 WORM 存储；哈希链只能证明"是否被改"，不能阻止有权限者删除整个文件，物理保全仍需存储层配合。

## 五、多租户

### 5.1 目录布局

```
<FH_HOME>/
├── policy.json                     全局策略（可选）
└── tenants/
    ├── acme/
    │   ├── sessions/               会话检查点 + 事件日志
    │   ├── audit/                  审计链
    │   ├── goals/                  /goal 产物
    │   └── policy.json             租户策略（可选）
    └── beta/
        └── …
```

`sessions` / `resume` / `diff` / `rollback` / `audit` / `goal` 全部在当前租户目录内操作，**跨租户不可见**。

### 5.2 用量汇总

```bash
$ fhcode tenants
租户用量汇总:
  租户ID                会话数   累计成本      审计条数   最近活跃
  beta                     1   $  0.000000         3   2026-08-10T06:42:00.496Z
  acme                     2   $  0.420000         6   2026-08-10T06:41:59.599Z
```

统计不反序列化整份对话（仅正则提取 `costUsd` / `updatedAt`），万级会话下依然秒回。

### 5.3 升级兼容

默认租户（`default`）在 `tenants/default` 尚未创建、而旧版 `<FH_HOME>/sessions` 存在时，会自动继续使用旧目录——**从 M3 升级到 M4 不丢历史会话**。

### 5.4 部署形态建议

| 形态 | 做法 | 适用 |
| --- | --- | --- |
| 单机多租户 | 同一 `FH_HOME`，靠 `FH_TENANT` 分目录 | 内部多团队 |
| 容器一租户一实例 | 每租户独立容器 + 独立卷，`FH_TENANT` 与卷同名 | 对隔离要求高 / 对外服务 |
| CI 每次任务一租户 | `FH_TENANT=ci-${{ github.run_id }}` | 流水线可追溯，任务间零串扰 |

## 六、成本治理

| 层级 | 配置 | 行为 |
| --- | --- | --- |
| 单任务 | 角色 `maxCostUsd` | 达到上限立即中止本次任务，检查点保留，可调高后 `resume` 续跑 |
| 租户日预算 | `FH_TENANT_BUDGET_USD` 或策略 `tenantDailyBudgetUsd` | 任务**启动前** fail-fast（`QUOTA_EXCEEDED`），不产生任何模型调用费用 |

统计口径：该租户 `sessions` 目录下 `updatedAt` 为当天（UTC）的检查点 `costUsd` 之和。拒绝时同步写入 `quota:block` 审计记录。

```bash
$ FH_TENANT_BUDGET_USD=0.30 fhcode "超预算任务"
[飞虹 Code] 运行失败 (QUOTA_EXCEEDED): 租户 acme 今日成本 $0.420000 已达上限 $0.3，任务被拒绝。
```

## 七、CI 集成

`.github/workflows/ci.yml` 三条流水线，**全程离线、零 Secrets**，fork PR 也能安全跑完：

| Job | 内容 |
| --- | --- |
| `build` | Node 18 / 20 / 22 矩阵 → typecheck → 编译 → 离线端到端 → `/plan` `/grill` |
| `enterprise` | `scripts/verify-m4.mjs` 41 项断言 + CLI 企业命令冒烟 + **租户隔离断言**（beta 租户读不到其它租户会话即通过） |
| `security` | `npm pack --dry-run` 白名单校验（`.env`/`src`/`policy.json` 出现即失败）+ 仓库明文密钥扫描 + `npm audit` |

本地一条命令跑齐：

```bash
npm run verify     # typecheck + build + M4 断言套件
```

### 断言覆盖（41 项）

1. RBAC 角色矩阵（5 项）
2. deny 优先危险动作（4 项）
3. 策略文件覆盖与"只能加严"（4 项）
4. 审计哈希链：写入 / 校验 / 脱敏 / 篡改定位 / 删除检测（7 项）
5. 守卫接入工具链：拦截、放行、审批一次、危险命令批准也拒（11 项）
6. 多租户：非法 ID、目录隔离、用量统计、不串台（7 项）
7. 配额：当日统计、超限、充足（3 项）

- [ ] `FH_HOME` 指向持久卷，`tenants/` 已纳入备份策略
- [ ] `FH_TENANT` / `FH_USER` / `FH_ROLE` 由上游身份系统注入，不由用户自填
- [ ] 生产角色最小化：默认 `developer`，`admin` 仅限平台管理员
- [ ] `policy.json` 已按业务补充禁止项（如 `kubectl delete`、生产配置目录）

- [ ] `FH_SHELL_ALLOW` 仅包含确需免审批的命令（建议 `git,npm,node,ls,cat`）
- [ ] 定时任务执行 `fhcode audit verify`，失败即告警
- [ ] 审计目录已归档至只读 / WORM 存储
- [ ] `.env` 未入库（`git check-ignore .env` 应有输出）
- [ ] 发布前执行 `npm pack --dry-run` 确认无密钥与源码泄漏
