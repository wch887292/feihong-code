---

## 1. 环境要求

- **Node.js >= 18**（CI 与 Docker 均使用 18）。
- **Git**：`--parallel` 依赖 `git worktree` 隔离，必须可用（Docker 镜像已内置）。
- 仅需运行时依赖 `zod`（dev 依赖 typescript/tsx 仅构建期需要）。

---

## 2. 从源码部署

```bash
git clone https://github.com/wch887292/feihong-code.git
cd feihong-code
npm install
npm run build
node dist/cli/index.js --version
```

或直接用脚本：`bash install.sh`（自动 install + build + 全局安装）。

---

## 3. 全局安装

```bash
npm install -g .          # 从本地源码装为全局命令 fhcode
fhcode --version
```

发布到 npm 后：`npm install -g feihong-code`。

---

## 4. Docker 部署

```bash
docker build -t feihong-code .
```

运行（离线）：

```bash
docker run --rm feihong-code --version
```

运行（真实模型，挂载密钥与日志）：

```bash
docker run --rm \
  -v "$PWD/.env:/app/.env" \
  -v feihong-data:/data/feihong-code \
  feihong-code "把 src/utils 的日期格式化抽成独立模块并补测试"
```

- 镜像为多阶段构建：构建期装全依赖编译 `dist`，运行期仅 `npm install --omit=dev` + 复制 `dist`。
- 运行期已 `apk add git`，支持 `--parallel` 的 worktree 隔离。
- `FH_HOME` 默认 `/data/feihong-code`，建议挂载为卷以持久化目标与日志。

## 5. CI / CD（M4 三流水线）

`.github/workflows/ci.yml` 在 `push`/`pull_request` 触发，**全离线、零 Secrets**，fork PR 安全。分为三个 job：

### 5.1 `build` — 构建与离线闭环

- Node 18 / 20 / 22 矩阵；
- `npm run typecheck` → `npm run build`；
- 离线冒烟：`FH_OFFLINE=true fhcode "..."`；只读技能 `/plan` `/grill` 校验；
- 目的：保证多版本 Node 下可构建、社区闭环可跑。

### 5.2 `enterprise` — 企业能力断言

- 运行 `npm run verify:m4`（`scripts/verify-m4.mjs`，**41 项全离线断言**）：
  - RBAC 矩阵(5) / deny 优先(4) / 策略覆盖(4) / 审计哈希链(7) / 守卫链路(11) / 多租户(7) / 配额(3)；
- CLI 冒烟：`whoami` / `policy` / `audit` / `audit verify` / `tenants`；
- **租户隔离断言**：用 `beta` 租户执行任务后，断言其 `sessions` 读不到 `acme` 租户会话（物理目录互不串台）。

### 5.3 `security` — 发布安全

- `npm pack --dry-run` 白名单校验：禁止 `.env` / `src` / `policy.json` / `.workbuddy` 进入产物；
- 仓库明文密钥扫描（`git grep` 规则集）：杜绝 accidental secret 入库；
- `npm audit`：依赖漏洞检查。

> 本地完整校验：`npm run verify`（= typecheck + build + verify:m4）。

- **企业模式不触碰密钥**：CI 仅做离线冒烟、企业断言与发布安全，**绝不**读取或回显任何 API key。
- 真实联调建议在本地或带加密 secret 的受控环境执行，切勿把密钥明文写入 CI 日志。

## 5.1 企业合规部署建议（M4）

- **多租户物理隔离**：为每个客户/团队分配独立 `FH_TENANT`，数据落 `<FH_HOME>/tenants/<tenantId>/`，互不串台。
- **最小角色**：日常运行用 `developer`；仅可信运维用 `operator`/`admin`；只读巡检用 `viewer`。
- **日预算硬上限**：为每个租户设 `FH_TENANT_BUDGET_USD`，超限即 `QUOTA_EXCEEDED` 拒绝，防成本失控。
- **审计留存**：`audit-YYYY-MM.jsonl` 建议只读挂载或异地备份，并周期性 `fhcode audit verify` 巡检哈希链完整性。
- **关闭企业模式**：纯社区/单机使用可设 `FH_ENTERPRISE=false`，行为与 M3 一致、零额外开销。

## 6. 发布到 npm

`package.json` 已做好发布安全：

- `files` 白名单：`dist` + `README.md` + `LICENSE` + `CONTRIBUTING.md` + `docs`（**绝不**包含 `.env` / `src` / `.workbuddy`）。
- `prepublishOnly`: `npm run build`（发布前自动构建，保证 `dist` 最新）。
- `.npmignore` 作为冗余保险。

发布步骤：

```bash
npm run build
npm version patch          # 或 minor/major
npm publish                # 仅携带 files 白名单内容
```

> ⚠️ **密钥安全铁律**：`.env` 含 API key，已被 `.gitignore` 与 `files` 白名单双重排除，永远不会进入 npm 包或 Git 仓库。

---

## 7. 内网 / 离线部署建议

- **完全离线**：不配 `FH_PROVIDERS`，用内置 Mock 闭环（演示/回归）。
- **本地模型**：配 Ollama 供应商（`type: ollama`，`baseURL: http://<内网IP>:11434`），数据不出本机。
- **代理网关**：OpenAI 兼容供应商的 `baseURL` 可指向企业内网网关。
- **日志合规**：`FH_LOG_DIR` 指向受控存储，按敏感数据留存策略管理。

## 8. 作为后台服务（可选 systemd）

```ini
[Unit]
Description=飞虹 Code Agent
After=network.target

[Service]
WorkingDirectory=/opt/feihong-code
ExecStart=/usr/bin/fhcode "守护型需求"
Environment=FH_HOME=/var/lib/feihong-code
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

## 9. 升级与回滚

- 升级：`git pull && npm install && npm run build`（或 `npm update -g feihong-code`）。
- 回滚：npm 包使用 `npm install -g feihong-code@<旧版本>`；源码用 `git checkout <tag>` 后重建。
