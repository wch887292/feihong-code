# 飞虹 Code 企业集成模板指南

> 晋江市飞虹智科技企业管理有限公司 · 飞扬企源研发中心 · 负责人：吴赐虹

本文档说明如何使用 fhcode 的**企业集成预置模板**，把 fhcode 快速接入企业现有的研发流程、协作平台与工单系统。

## 为什么需要它

fhcode 此前已具备飞书桥接、企业微信桥接、GitHub MCP 等能力，但这些能力的配置零散在代码注释与文档里，企业需要"自己抄环境变量、自己拼流水线"。本模板系统把它们收敛为**开箱即用的预置模板**，一条命令即可落地。

## 命令总览

```bash
# 列出全部预置模板（按 IM / CI/CD / 工单 三类分组）
fhcode integrations list

# 生成指定模板到当前工作区（文件已存在则不覆盖）
fhcode integrations init cicd-github

# 生成到指定目录
fhcode integrations init im-feishu ./deploy
```

生成后，`init` 命令会打印**部署步骤**，照着做即可。

## 模板清单

| 模板 ID | 类别 | 产出 | 说明 |
|---|---|---|---|
| `im-feishu` | 即时通讯 | `.env.example.feishu` | 飞书机器人双向桥接配置（依赖 `feishu-bridge.ts`） |
| `im-wecom` | 即时通讯 | `.env.example.wecom` | 企业微信/公众号双向桥接配置（依赖 `wechat-bridge.ts`） |
| `cicd-github` | CI/CD | `.github/workflows/fhcode-review.yml` + `scripts/fhcode-ci-review.mjs` | PR 自动 AI 评审并回写评论 |
| `cicd-gitlab` | CI/CD | `.gitlab-ci.yml` + `scripts/fhcode-ci-review.mjs` | MR 自动 AI 评审并回写评论 |
| `cicd-jenkins` | CI/CD | `Jenkinsfile` + `scripts/fhcode-ci-review.mjs` | 流水线阶段 AI 评审门禁 |
| `ticketing-jira` | 工单 | `.env.example.jira` + `scripts/fhcode-jira-bridge.mjs` | Jira 工单拉取→fhcode 处理→回写 |
| `ticketing-zentao` | 工单 | `.env.example.zentao` + `scripts/fhcode-zentao-bridge.mjs` | 禅道任务拉取→fhcode 处理→回写 |

## 场景一：IM 双向桥接（飞书 / 企微）

**价值**：员工在飞书/企微对话框直接说"帮我审查这段代码""生成一份分钱模式方案"，fhcode 在后台执行并把结果以卡片/消息主动推回。无需登录终端。

**步骤**：
1. `fhcode integrations init im-feishu`（或 `im-wecom`）
2. 按打印步骤在开放平台配置回调地址、订阅事件、开通权限
3. 把生成的 `.env.example.*` 内容并入 `.env`，填真实密钥
4. `fhcode serve` 启动，对话验证

**安全**：入站消息强制签名校验（fail-closed），加密消息强制 AES 解密，access_token 内存缓存自动刷新，用户会话隔离。

## 场景二：CI/CD AI 评审门禁

**价值**：每次 PR/MR 自动调用 fhcode 做 AI 代码评审（bug、安全漏洞、规范），评审结论回写到 PR 评论或构建日志，可作为合并门禁。

**步骤**：
1. `fhcode integrations init cicd-github`（或 `cicd-gitlab` / `cicd-jenkins`）
2. 在对应平台的 Secrets/CI Variables 中配置 `FH_API_BASE` / `FH_API_KEY` / `FH_DEFAULT_MODEL`（**绝不硬编码**）
3. 提交生成的 workflow/Jenkinsfile 与 `scripts/fhcode-ci-review.mjs`
4. 创建 PR 触发，观察评审意见自动出现

**可扩展**：`fhcode-ci-review.mjs` 仅依赖 Node 内置 `fetch`，可按团队规范自定义评审目标与门禁阈值。

## 场景三：工单系统对接（Jira / 禅道）

**价值**：fhcode 定时拉取待处理工单/任务，自动生成开发目标并执行，结果回写到工单备注，形成"工单→代码→回执"闭环。

**步骤**：
1. `fhcode integrations init ticketing-jira`（或 `ticketing-zentao`）
2. 并入 `.env` 配置，填真实凭据
3. 试运行 `node scripts/fhcode-jira-bridge.mjs` 验证连通
4. 结合 fhcode routine 定时执行：`fhcode routine add --cron "0 9 * * *" --command "node scripts/fhcode-jira-bridge.mjs"`

## 设计原则

- **密钥零硬编码**：所有敏感信息通过环境变量 / 平台 Secrets 注入。
- **失败 fail-closed**：脚本出错即 `process.exit(1)`，不静默吞错。
- **不覆盖既有文件**：`init` 遇到已存在文件会跳过并提示，保护用户配置。
- **离线友好**：桥接层支持 `FH_*_OFFLINE=true` 的 mock 模式，无 API Key 也能验证链路。

## 与「系统集成」评估的关系

此前评估报告中 fhcode「系统集成」维度为中等偏弱（缺开箱即用模板）。本模板系统正是补齐这一项——从"有接口可对接"升级为"一键落地、带部署脚本与文档"。
