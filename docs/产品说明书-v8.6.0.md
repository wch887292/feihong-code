## 一、产品概述

飞虹 Code（fhcode）是一款运行在终端的 **AI 编程智能体**，以 Meta Muse Code、Claude Code、Cursor CLI 为对标参照系，**独立自研内核**（TypeScript 5.x，非分叉非移植）。用自然语言描述需求，智能体自主完成「规划 → 读写代码 → 运行验证 → 汇报结果」闭环。

**核心卖点**：

| 能力 | 说明 |
|---|---|
| 多模型路由 | DeepSeek / 通义 / Ollama（本地）/ 任意 OpenAI 兼容网关按成本与能力动态调度 |
| 离线可用 | 未配 API Key 时内置 Mock 驱动完整闭环；Ollama 本地推理数据不出内网 |
| 企业级治理 | RBAC 四角色矩阵 + 防篡改审计哈希链 + 多租户物理隔离 + 成本配额熔断 |
| 全自动 SWE Agent | 读仓库 → 拆解任务 → 实现 + 测试验证 → 自愈重试 → 报告（M9/M9.1） |
| 自我进化 | 经验库沉淀 + 自愈循环，失败模式跨会话复用（M6） |
| Always-on（v8.6.0） | Agent 自我认知、透明记忆、Routines 定时调度、三级规则引擎 + 审批收件箱 |

**质量基线（v8.6.0 实测）**：单元测试 **354/354** 全绿；端到端验证链十项 **165 项**全绿（m4 41 + m6 29 + m7 12 + m8 27 + m9 25 + routines 18 + policy 13）；typecheck 零错误。

**里程碑**：M0→M9.1 全部交付并冻结；8.x 为产品化成熟度版本号（SemVer）。

## 二、安装部署

### 2.0 环境要求

| 项 | 要求 |
|---|---|
| Node.js | **>= 22.5.0**（推荐 22 LTS / 24） |
| 操作系统 | Windows 10/11、Linux（Ubuntu/Debian/OpenCloudOS 等）、macOS |
| 网络 | 可选：离线可用（Mock/Ollama 本地模式无需外网） |
| 磁盘 | ≥ 500MB（npm 包解压约 34MB，另含会话/审计数据） |
| Git | 推荐（`--parallel` 并行子代理与 diff/rollback 依赖 git） |

### 2.1 方式一：npm 全局安装（推荐）

```bash
# 官方源
npm install -g feihong-code

# 国内镜像加速
npm install -g feihong-code --registry=https://registry.npmmirror.com

# 验证
fhcode --version        # 输出版本号 + 署名
fhcode --help           # 查看全部命令
```

> Windows 下实际入口为 `fhcode.cmd`，npm 已自动处理。

### 2.2 方式二：源码构建（开发 / 内网定制）

```bash
git clone https://github.com/wch887292/feihong-code.git
cd feihong-code
npm install
npm run build              # tsc 编译到 dist/ + 复制 Web 静态资源
node dist/cli/index.js --version

# 或使用一键安装脚本
bash install.sh
```

开发模式（免构建）：

```bash
npm run dev                # tsx 直接跑源码
npm run typecheck          # 仅类型检查
npm test                   # 全量单元测试（354 项）
npm run verify             # verify 链十项一条命令全过
```

### 2.3 方式三：Docker

```bash
docker build -t feihong-code .
docker run --rm feihong-code --version

# 挂载密钥与数据卷启用真实模型
docker run --rm \
  -v "$PWD/.env:/app/.env" \
  -v feihong-data:/data/feihong-code \
  feihong-code "你的需求"
```

### 2.4 方式四：桌面安装包（Windows）

| 安装包 | 说明 |
|---|---|
| `飞虹 Code Setup <版本>.exe` | NSIS 安装向导：可选安装目录、创建桌面/开始菜单快捷方式 |
| `飞虹Code-Portable-<版本>.exe` | 免安装绿色版，双击即用 |

安装完成后从「开始菜单 → 飞虹 Code」启动桌面版；终端内 `fhcode` 命令需另行通过 npm 安装或使用安装包内置环境。

Linux（AppImage / deb）与 macOS（zip / dmg）安装包由 GitHub Actions 按版本 tag 自动构建发布：https://github.com/wch887292/feihong-code/releases

### 2.5 安装验证清单

```bash
fhcode --version            # ① 版本号正确
fhcode "写一个 hello.ts"     # ② 离线模式跑通闭环（无需任何 Key）
fhcode whoami               # ③ 企业身份就绪（租户/用户/角色）
fhcode license show         # ④ 授权状态可见
```

四项全过即安装成功。

## 三、授权与激活

### 3.1 双轨授权模式

| 轨道 | 范围 | 费用 |
|---|---|---|
| **开源轨道** | 全部源代码（Apache-2.0）：CLI、多模型路由、企业级 RBAC/审计/多租户、SWE Agent、自进化 | 免费，可自托管、可二次开发（遵守 Apache-2.0） |
| **商业轨道** | 企业版增值能力：激活码授权、完全私有化部署支持、授权范围内二次开发服务、技术支持 | 按授权类型购买 |

### 3.2 授权类型

| 类型 | 适用 | 说明 |
|---|---|---|
| 试用期 | 全部新装机 | 安装即含试用期功能，试用结束后需激活码解锁 |
| `standard` | 个人/小团队 | 标准授权 |
| `pro` | 专业团队 | 进阶授权 |
| `enterprise` | 企业客户 | 企业授权（含私有化部署支持） |

### 3.3 授权命令

```bash
# 查看当前授权状态（类型/到期时间/设备指纹）
fhcode license show

# 激活（购买后获得激活码）
fhcode license activate <你的激活码>

# 打印本机设备指纹（绑定授权用）
fhcode license fingerprint
```

激活成功后输出授权类型、绑定客户名、到期时间与设备指纹。激活码与设备指纹绑定，迁移机器需重新签发。

### 3.4 开发商发码（双重密钥门禁）

仅授权运营商可发码，需同时持有两把密钥：

```bash
# 环境变量注入（勿入库、勿入聊天记录）
export FH_LICENSE_SIGN_PRIVATE_KEY=...   # Ed25519 私钥（签名）
export FH_LICENSE_MASTER=...             # 开发商主密钥

# 生成：类型 客户名 [天数] [设备数]
fhcode license gen enterprise "某某制造有限公司" 365 10
```

安全机制：**Ed25519 非对称签名**——服务端持私钥签发，客户端仅内嵌公钥验签，无私钥无法伪造激活码；本地自测需显式 `FH_LICENSE_DEV=1`。生产环境缺失发码私钥时 `license gen` 直接拒绝。

### 3.5 授权相关环境变量

| 变量 | 用途 |
|---|---|
| `FH_LICENSE_SIGN_PRIVATE_KEY` | 发码 Ed25519 私钥（仅开发商侧） |
| `FH_LICENSE_MASTER` | 开发商主密钥（仅开发商侧） |
| `FH_LICENSE_SIGN_PUBLIC_KEY` | 验签公钥（覆盖内置公钥，可选） |
| `FH_LICENSE_DEV` | `1` = 本地自测模式（禁止用于生产签发） |

## 四、快速上手（5 分钟）

### 4.1 离线模式（无需任何 API Key）

```bash
fhcode "帮我写一个 hello.ts 并打印一句话"
```

未配置 `FH_PROVIDERS` 时自动进入离线模式，用内置 Mock 驱动跑通「规划 → 调工具写文件 → 总结」完整闭环——适合安装验证、教学演示、CI 冒烟。

### 4.2 接入真实大模型

```bash
cp .env.example .env
# 编辑 .env 填入 FH_PROVIDERS（baseURL / apiKey / model）
fhcode "把 src/utils 的日期格式化抽成独立模块并补测试"
```

`.env` 示例（OpenAI 兼容网关通用写法）：

```bash
FH_PROVIDERS='[{"id":"agnes","type":"openai-compatible","baseURL":"https://api.agnes-ai.cn/v1","apiKey":"<你的key>","model":"agnes-2.5-flash","tags":["code-gen"],"costPer1k":0.001}]'
```

本地 Ollama（完全离线）：

```bash
export FH_MODEL_NAME=qwen3:8b
export FH_MODEL_TYPE=ollama
export FH_MODEL_BASE_URL=http://localhost:11434
fhcode "审查 src/security 的边界校验"
```

### 4.3 三种工作方式

```bash
fhcode                          # ① REPL 交互：逐条输入需求，exit 退出
fhcode "<需求>"                  # ② 单命令：一条需求一次执行
fhcode --parallel "<A> 并且 <B> 并且 <C>"   # ③ 并行：自动拆子任务各自隔离执行
```

### 4.4 只读技能

```bash
fhcode /plan  "实现登录并且添加支付"   # 生成结构化实现计划（不改代码）
fhcode /grill src                    # 红队式代码审查
fhcode /goal  "搭建多子代理体系"      # 分解并保存高层目标
```

### 5.1 命令总览

| 命令 | 功能 | 来源 |
|---|---|---|
| `fhcode` / `fhcode "<需求>"` | REPL / 单命令执行 | M0-M1 |
| `fhcode --parallel "<需求>"` | 多子代理并行（git worktree 隔离） | M2 |
| `fhcode /plan` `/grill` `/goal` | 只读技能三件套 | M2 |
| `fhcode sessions` | 列出历史会话检查点 | M3 |
| `fhcode resume <id>` | 断点续跑中断任务 | M3 |
| `fhcode diff [<id>]` | 会话作用域变更比对 | M3 |
| `fhcode rollback <id> --yes` | 回滚会话改动（需确认） | M3 |
| `fhcode whoami` | 当前租户/用户/角色/今日用量 | M4 |
| `fhcode policy` | 生效 RBAC 策略与角色矩阵 | M4 |
| `fhcode audit [--limit N]` | 审计记录查看 | M4 |
| `fhcode audit verify` | 校验审计哈希链完整性 | M4 |
| `fhcode tenants` | 全部租户用量汇总 | M4 |
| `fhcode model-stats` | 模型性能统计 | M6 |
| `fhcode experiences` | 经验库列表 | M6 |
| `fhcode code-write "<目标>"` | 自主编码六步闭环 | M8 |
| `fhcode quality-gate [路径]` | 质量门禁（安全+质量+覆盖） | M8 |
| `fhcode self-improve` | 自我改进统计 | M8 |
| `fhcode swe "<目标>"` | 全自动软件工程 Agent | M9 |
| `fhcode serve` | Web 管理控制台 | M5 |
| `fhcode license show/activate/fingerprint/gen` | 授权管理 | 商业轨道 |
| `fhcode --version` / `--help` | 版本与帮助 | — |

### 5.2 会话恢复与审计（M3）

每次任务将完整对话、迭代计数、成本、被改动文件落盘为检查点（`<runId>.session.json`）：

```bash
fhcode sessions            # 状态/迭代/成本/文件数一览
fhcode resume <id>         # 从检查点续跑（进程崩溃/达到迭代上限后）
fhcode diff <id>           # 仅对本会话 touchedFiles 生成 git diff
fhcode rollback <id> --yes # 回滚该会话改动（未确认或非 git 仓库时拒绝）
```

- 会话 id 支持 8 位前缀。
- `diff` 绝不整仓比对；`rollback` 未跟踪文件直接删除、已跟踪文件 `git checkout --`，**必须 `--yes`**。

### 5.3 企业能力（M4）

企业模式默认开启（`FH_ENTERPRISE=false` 关闭），身份经环境变量注入：

```bash
export FH_TENANT=acme      # 租户 ID
export FH_USER=wuchihong   # 用户标识
export FH_ROLE=developer   # viewer | developer | operator | admin
```

**RBAC 四角色矩阵**：

| 角色 | 直接允许 | 需审批 | 单任务成本上限 |
|---|---|---|---|
| `viewer` | read_file / list_dir / grep | — | $0.1 |
| `developer` | 上述 + write_file / edit_file / run_tests / build_check | run_shell | $1 |
| `operator` | 全部工具 | run_shell | $5 |
| `admin` | 全部工具 | run_shell | 不限 |

判定顺序：**危险命令黑名单 → 敏感路径黑名单 → 沙箱越界 → 角色矩阵 → shell 白名单**。前三条 deny 优先，`admin` 也无法绕过。策略可用 `policy.json` 逐级覆盖（全局 → 租户 → `FH_POLICY` 内联），**黑名单取并集只能加严不能放松**。

**防篡改审计哈希链**：每条记录携带 `prevHash` + 自身 sha256，改写/删除/插入都会断链，`fhcode audit verify` 可定位断点；审计内容自动脱敏；**审计写失败即拒绝执行**。

**多租户物理隔离**：`<FH_HOME>/tenants/<租户>/` 下 sessions / audit / goals 分目录互不可见；租户 ID 正则校验杜绝路径穿越；升级自动沿用旧版目录不丢历史。

**配额熔断**：单任务超角色 `maxCostUsd` 立即中止（可调高后 `resume`）；租户日预算 `FH_TENANT_BUDGET_USD` 启动前 fail-fast，**不产生任何模型费用**。

### 5.4 编程增强（M7-M9）

```bash
fhcode code-write "实现配置热加载模块"        # 规划→编写→测试→审查→修复→交付
fhcode quality-gate src/                     # 安全+质量+测试覆盖三门禁
fhcode swe "修复仓库里 CI 挂掉的那条用例"      # 全自动：读仓库→拆解→实现+验证→自愈→报告
fhcode swe "<目标>" --max-iterations 10      # 限制迭代上限
```

- **CodeWriter 六步闭环**（M8）：规划 → 编写 → 运行测试 → AI 审查 → 修复 → 交付。
- **QualityGate**：静态分析 + 质量评分 + 覆盖率门禁，不达标不放行。
- **SWE Agent**（M9/M9.1）：真实模型三级 provider 解析；预定义测试真实断言（测试不交给模型，防作弊）；自建任务集实测 5/5 全过（诚实口径，非官方 Verified 500 榜单成绩）。

### 5.5 自我进化（M6）

```bash
fhcode model-stats     # 各模型成功率/延迟/成本追踪
fhcode experiences     # 经验库：失败模式→修复经验跨会话复用
```

自愈循环：任务失败自动诊断 → 尝试修复 → 沉淀经验；上下文智能压缩控制长任务成本。

### 5.6 Web 管理控制台（M5 BETA）

### 5.7 AI 员工军团（agent-team）

## 六、v8.6.0 新功能详解（Always-on 飞虹 dots）

> v8.6.0 借鉴 OpenAI dots 范式完成四期升级，主打「全天候 Agent 的三块基石」：知道自己能干什么（自我认知）、记住发生过什么（透明记忆）、按计划自主干活且不越权（Routines + 规则引擎）。四个模块均为**内核层能力**，已全量测试覆盖，CLI/Web 直接命令入口将随后续版本逐步开放；本节同时给出当前可用的调用方式。

### 6.1 P1 Agent 自我认知

**是什么**：Agent 启动时自动把**运行时工具注册表**（21 个工具）自省注入系统提示词——它明确知道自己有哪些工具、每个工具参数怎么传、失败如何降级，而不是依赖一份可能过期的静态清单。

**用与不用**：

```bash
fhcode "任意任务"                 # 默认开启，无需配置
FH_NO_SELF_AWARENESS=1 fhcode ... # 需要回到基础提示词时禁用
node scripts/gen-tool-schema.ts   # 开发者：从运行时重新生成 tool-schema.json
```

**价值**：工具清单以**代码为单一事实源**（注册表 > schema 文件双来源），来源损坏自动回退不阻断任务；模型对工具的调用准确率与幻觉率因此改善。

### 6.2 P2 透明记忆

**是什么**：Agent 的长期记忆**可读、可编辑、可导出**——对比同类产品「记忆不可查看、不可带走」的封闭设计，飞虹的记忆归用户所有。

**能力**：

- 增 / 列 / 搜 / 改 / 删：记忆条目全生命周期管理（内容、分类、重要度）；
- `exportJson` / `exportMarkdown` / `importJson`：全量导出为 JSON / Markdown、再导入恢复（round-trip 校验）；
- 导出默认过 **audit.redact 脱敏**（apiKey / Bearer / sk-xxx → `***`），带出去不泄密；
- 存储层 userId + id 双条件防越权（A 用户改不到 B 用户的记忆）。

**当前调用**：内核模块 `src/memory/transparent.ts`（`TransparentMemory` 类），格式 `feihong-transparent-memory v1`。Web 控制台记忆面板与 CLI 命令将随后续版本开放。

### 6.3 P3 Routines 调度（定时任务引擎）

**是什么**：给 Agent 配一个「闹钟 + 计划表」——cron 定时任务、事件触发、错过补偿，让 Agent 具备全天候自主干活的基础。

**能力**：

| 特性 | 说明 |
|---|---|
| 五字段 cron | `分 时 日 月 周`，支持宏（`@hourly` `@daily` `@midnight`）、步进 `*/15`、区间 `a-b/n` |
| 事件触发 | `notifyEvent(event)` 直接触发，不等时钟 |
| 错过补偿 | Agent 停机期间错过的任务，重启后 **catchup 恰好补跑一次**（可按任务关闭） |
| 互斥与并发 | 同一任务运行中不重入；全局并发上限默认 3 |
| 失败退避 | 指数退避重试（默认 `maxRetries=2`，间隔 `base×2^(n-1)` 秒），重试用尽停止 |
| 持久化 | 任务定义与状态 JSON 原子写落盘，重启不丢、不重派 |

**当前调用**：内核模块 `src/runtime/routines/`（`RoutineScheduler` / `RoutineStore`），任务定义示例：

```json
{
  "id": "nightly-audit",
  "name": "每晚审计巡检",
  "trigger": { "kind": "cron", "expr": "0 2 * * *" },
  "action": { "type": "noop", "note": "占位动作，接审批门控后执行真实任务" },
  "enabled": true,
  "catchUp": true,
  "maxRetries": 2
}
```

> 诚实说明：当前版本调度器动作执行为 noop 占位（引擎与状态机已全量测试），真实动作将在「Routines × 审批收件箱」接线版本开放。

### 6.4 P4 三级规则引擎 + 审批收件箱

**是什么**：dots 范式的权限核心——Agent 每个动作先过三级判定：**allow（直接放行）/ ask（进审批收件箱等人裁决）/ deny（直接拦截）**。

**判定顺序**（红线永远最高）：

```
① 硬红线四类（内置，任何规则不可放行）
   ├─ 改密码（passwd / 修改密码 / change password …）
   ├─ 转账（转账 / 汇款 / transfer money …）
   ├─ 永久删除（rm -rf / del /f / format C: / DROP TABLE …）
   └─ 外发（外发 / 外部 POST / curl -d …）
② 精确匹配用户规则（全等）
③ 通配匹配用户规则（单 * 通配，如 shell:rm *）
④ 默认 fail-safe：ask（宁可多问，不可放行）
```

- 同一动作命中多条规则时**取最严**（deny > ask > allow）；
- 禁用规则（`enabled: false`）不参与匹配；
- 词表中英双语、大小写不敏感。

**审批收件箱**：

```
submit ──→ pending ──decide(approve)──→ approved ✓（留痕：谁、何时批准）
                ├──decide(reject)───→ rejected ✗
                └──超时未决────────→ expired（需重新提交）
```

- **裁决幂等**：已决事项不可二次裁决，状态不被改写；
- **TTL 过期**：可设审批有效期，到点自动转 expired；
- **持久化**：`approvals.json` 原子写，重启队列不丢；
- **审计入链**：提交与裁决事件写入 M4 防篡改哈希链，`fhcode audit verify` 可验证；
- **凭证隔离**：队列落盘前先脱敏，审批文件里永远没有密钥明文。

**当前调用**：内核模块 `src/security/rules-engine.ts`（`evaluateRules` / `detectRedline`）与 `src/security/approval-inbox.ts`（`ApprovalInbox`）。用户规则集的 CLI 管理命令将随后续版本开放；今天的 CLI 交互审批（`y/n` 弹窗）与白名单审批器行为不变。

## 八、安全模型

1. **路径沙箱**：所有文件路径 `safeJoin` 校验不得越出 `cwd`，杜绝 `../` 穿越。
2. **Shell 白名单**：`run_shell` 仅放行 `FH_SHELL_ALLOW` 命中的首词；非交互回退白名单审批器，其余拒绝并留痕。
3. **危险命令黑名单**：`rm -rf /`、`mkfs`、`curl | sh` 等 23 条命令 + `.env`/`.ssh/id_rsa`/`.npmrc`/`.kube/config` 等 11 类敏感路径，**admin 不可绕过**。
4. **密钥脱敏**：日志与审计按 key 名（apikey/secret/token/authorization…）值替换为 `***`；Bearer/JWT/sk- 前缀令牌一律打码。
5. **三级规则引擎（v8.6.0）**：allow/ask/deny + 硬红线四类不可覆盖 + fail-safe 默认 ask。
6. **防篡改审计链**：sha256 哈希链 append-only，写失败即拒执行；`fhcode audit verify` 定位篡改。
7. **多租户隔离**：物理目录 + ID 正则校验。
8. **成本硬闸**：`FH_BUDGET_USD` 环境变量优先于角色策略；租户日预算启动前 fail-fast。
9. **授权验签**：Ed25519 非对称签名激活码，客户端无私钥不可伪造。
10. **桌面手脚停手线**：任务管理器/注册表/UAC/安全中心等危险窗口硬拦截。

> 完整安全白皮书见 `docs/SECURITY_WHITEPAPER.md` 与 `docs/安全白皮书_v7.2.0.md`。

## 十、故障排查 FAQ

| 现象 | 原因与处理 |
|---|---|
| `fhcode` 命令不存在 | Node >= 22.5 未满足，或 npm 全局 bin 未在 PATH；Windows 用 `fhcode.cmd` |
| 离线模式跑通了但想用真实模型 | 配置 `.env` 的 `FH_PROVIDERS`（见 4.2），或 `FH_OFFLINE=true` 显式离线 |
| 并行任务报 HTTP 429 | 免费 API 套餐并发限流；升级套餐 / 改单命令 / `FH_OFFLINE=true` 验证机制 |
| 任务被 QUOTA_EXCEEDED 中止 | 超过角色 `maxCostUsd` 或租户日预算；调高后 `fhcode resume <id>` 续跑 |
| 审计链校验失败 | 有人/有进程改写过审计文件；按断点提示排查，必要时从备份恢复 |
| `license gen` 提示未配置私钥 | 生产发码需 `FH_LICENSE_SIGN_PRIVATE_KEY` + `FH_LICENSE_MASTER`；本地自测设 `FH_LICENSE_DEV=1` |
| 激活失败 | 核对激活码与设备指纹绑定；`fhcode license fingerprint` 后联系发码方重新签发 |
| Web 控制台打不开 | 确认 `fhcode serve` 在跑、端口未被占用（`FH_WEB_PORT`）；浏览器访问 `http://localhost:8080` |
| Ollama 连不上 | 确认 `ollama serve` 在跑且 `FH_MODEL_BASE_URL` 指向正确端口 |
| 中文/英文切换 | `fhcode --lang zh` / `FHCODE_LANG=zh` |

更多：`docs/常见问题与故障排查.md`、错误码字典 `docs/error-codes.md`。
