## 一、部署形态总览

| 形态 | 场景 | 组件 |
|------|------|------|
| 单机 CLI | 个人开发 / 内网终端 | fhcode CLI（Node.js） |
| Web 服务 | 团队共享 / 云执行 | fhcode serve + 任务队列 |
| Docker | 容器化 / 私有化 | Dockerfile + docker-compose |
| 企业私有化 | 多租户 / 审计 / 配额 | 企业模式（FH_ENTERPRISE） |
| IDE 集成 | 编辑器内使用 | VSCode 扩展（薄壳） |

## 二、环境要求

| 项 | 要求 | 说明 |
|----|------|------|
| Node.js | ≥ 18（推荐 20/22） | 运行时 |
| npm | ≥ 9 | 包管理 |
| git | 推荐 | diff/rollback/并行 worktree |
| Docker | 可选 | `FH_SANDBOX_MODE=container` 与 Docker 部署 |
| 网络 | 可选 | 真实模型 API / 技能市场 / HF 数据集（离线模式不需外网） |

**离线部署要点**：未配置模型时自动进入离线模式（Mock 驱动），零外网依赖；模型接入可指向内网 Ollama 或私有 OpenAI 兼容网关。

## 三、安装部署

### 3.1 npm 全局安装

```bash
npm install -g feihong-code
fhcode --version
```

### 3.2 源码部署

```bash
git clone https://github.com/wch887292/feihong-code.git
cd feihong-code
npm install
npm run build          # tsc + Web 静态资源复制
npm test               # 164 单测自检
node scripts/eval.mjs  # 本地跑分自检（10/10）
```

### 3.3 Docker 部署（Web 服务）

```bash
# 构建镜像
docker build -t feihong-code .

# 运行 Web 控制台（含任务队列）
docker run -d --name fhcode \
  -p 8080:8080 \
  -e FH_WEB_TOKEN=<你的令牌> \
  -e FH_PROVIDERS='[{"name":"deepseek","type":"openai-compatible","baseUrl":"https://api.deepseek.com/v1","apiKey":"sk-...","tags":["code-gen"]}]' \
  -v fhcode-data:/root/.feihong-code \
  feihong-code
```

### 3.4 docker-compose（推荐）

```yaml
# docker-compose.yml
services:
  fhcode:
    build: .
    ports: ["8080:8080"]
    environment:
      FH_WEB_TOKEN: ${FH_WEB_TOKEN}
      FH_PROVIDERS: ${FH_PROVIDERS}          # 模型配置
      FH_TASK_CONCURRENCY: "2"               # 任务并发上限
      FH_TASK_PERSIST_DIR: /data/tasks       # 任务持久化（重启恢复）
      FH_ENTERPRISE: "true"                  # 企业模式
    volumes:
      - fhcode-data:/data
      - fhcode-home:/root/.feihong-code
volumes:
  fhcode-data:
  fhcode-home:
```

## 四、环境变量参考（完整）

### 4.1 应用与路径

| 变量 | 默认 | 说明 |
|------|------|------|
| `FH_HOME` | `~/.feihong-code` | 主目录（会话/审计/经验/统计/缓存） |
| `FH_LOG_DIR` | `$FH_HOME/sessions` | 会话日志目录（支持 `~` 展开） |
| `FH_CONFIG` | — | 配置文件路径（fhcode.config.json） |
| `FHCODE_LANG` | 系统 locale | 界面语言 zh/en |

### 4.2 模型路由

| 变量 | 说明 |
|------|------|
| `FH_PROVIDERS` | JSON 数组（最高优先级）：`{name,type,baseURL,apiKey,tags[],costPer1k}` |
| `FH_MODEL_NAME/TYPE/BASE_URL/API_KEY/TAGS/COST_PER_1K` | 单变量快速接入 |
| `FH_MODEL_STRATEGY` | cost/capability/latency |
| `FH_BUDGET_USD` | 单任务成本上限（熔断） |
| `FH_TENANT_BUDGET_USD` | 租户日成本上限（覆盖策略） |

### 4.3 安全

| 变量 | 说明 |
|------|------|
| `FH_SANDBOX_MODE` | read-only / workspace-write / danger-full-access / container |
| `FH_SANDBOX_IMAGE` | container 模式镜像（默认 node:22-alpine） |
| `FH_SHELL_ALLOW` | shell 白名单（逗号分隔） |
| `FH_REQUIRE_APPROVAL` | 审批开关（默认 true） |
| `FH_NETWORK_ALLOW/DENY` | 网络域名规则（deny 全模式生效） |
| `FH_HOOKS` | hooks JSON 数组（PreToolUse/PostToolUse/PostEdit） |
| `FH_POLICY` | 内联策略 JSON（RBAC/黑名单，仅加严） |

### 4.4 企业模式

| 变量 | 说明 |
|------|------|
| `FH_ENTERPRISE` | 默认开启（false 关闭退化为社区版） |
| `FH_TENANT` | 租户 id（缺省 default） |
| `FH_USER` | 用户 id |
| `FH_ROLE` | viewer/developer/operator/admin |

### 4.5 Web / 云执行

| 变量 | 说明 |
|------|------|
| `FH_WEB_TOKEN` | Web 控制台访问令牌（缺省自动生成） |
| `FH_WEB_PORT` | 端口（缺省 8080） |
| `FH_TASK_CONCURRENCY` | 任务并发上限（缺省 2） |
| `FH_TASK_PERSIST_DIR` | 任务持久化目录（缺省 `$FH_HOME/tasks`） |
| `FH_TASK_WEBHOOK_URL` | 任务状态 webhook（可动态注册） |

### 4.6 消息渠道

| 变量 | 说明 |
|------|------|
| `FH_CHANNEL_TELEGRAM_BOT_TOKEN/CHAT_ID` | Telegram 通知 |
| `FH_CHANNEL_WECOM_KEY` | 企业微信机器人 key（可多个逗号分隔） |
| `FH_CHANNEL_ALLOW` | 出站渠道白名单 |

### 4.7 技能市场 / 基准

| 变量 | 说明 |
|------|------|
| `FH_SKILL_MARKET` | 技能市场源（缺省 agentskills.io） |
| `FH_SWEBENCH_DATA_URL` | SWE-bench 数据镜像/离线 JSON（国内网络友好） |

## 五、企业私有化部署

### 5.1 目录结构（租户隔离）

```
$FH_HOME/
├── tenants/<tenantId>/
│   ├── sessions/          # 会话检查点
│   ├── audit/             # 审计哈希链（audit-YYYY-MM.jsonl）
│   └── goals/             # 目标文件
├── policy.json            # 全局策略（RBAC/黑名单）
├── experiences/           # 经验库
├── model-stats.jsonl      # 模型统计
├── skills/                # 用户级技能
├── plugins/               # 用户级插件
└── bench/                 # eval/SWE-bench 缓存与基线
```

### 5.2 生产建议

1. **令牌管理**：`FH_WEB_TOKEN` 必须显式设置（缺省自动生成仅限本会话），通过密钥管理服务注入
2. **审计合规**：`fhcode audit verify` 定期校验哈希链完整性；审计文件按月分片便于归档
3. **配额治理**：`FH_TENANT_BUDGET_USD` 设租户日预算，超限 fail-fast 拒绝任务
4. **备份**：`$FH_HOME`（会话/审计/经验）建议每日备份；任务队列 `FH_TASK_PERSIST_DIR` 独立卷
5. **多实例**：任务队列按文件持久化，多实例共享持久化目录可交叉恢复（queued 重新入队、running 僵尸标记 failed）
6. **内网模型**：`FH_PROVIDERS` 指向内网 Ollama/私有网关，可完全断外网运行

### 5.3 安全基线（生产必须）

```bash
export FH_REQUIRE_APPROVAL=true
export FH_SANDBOX_MODE=workspace-write     # 或 container
export FH_NETWORK_DENY=...                 # 按需配置
export FH_ENTERPRISE=true
export FH_CHANNEL_ALLOW=telegram,wecom     # 渠道白名单（可选）
```

## 六、Web 服务运维

### 6.1 启动与健康检查

```bash
fhcode serve --port 8080
curl http://localhost:8080/api/health   # 免鉴权健康检查
```

### 6.2 任务队列 API（Bearer 鉴权）

```bash
TOKEN=$FH_WEB_TOKEN
# 提交 / 列表 / 查询 / webhook 注册
curl -X POST http://localhost:8080/api/tasks -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"goal":"..."}'
curl http://localhost:8080/api/tasks -H "Authorization: Bearer $TOKEN"
curl http://localhost:8080/api/tasks/<id> -H "Authorization: Bearer $TOKEN"
curl -X POST http://localhost:8080/api/webhook -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" -d '{"url":"https://ci.example.com/hook"}'
```

### 6.3 重启恢复

- 任务落盘 `$FH_HOME/tasks/<id>.json`（原子写）
- 重启后：queued 重新入队执行、running 僵尸标记 failed、终态保留可查询
- webhook/渠道通知在恢复时重新触发（queued 节点）

  run: |

## 九、故障排查

| 现象 | 排查 |
|------|------|
| 服务启动后 401 | `FH_WEB_TOKEN` 未设置或与调用方不一致（Bearer 头） |
| 任务一直 queued | 并发满（`FH_TASK_CONCURRENCY`）或持久化目录不可写 |
| 模型调用失败 | `fhcode doctor` 检查网络连通与 provider 配置 |
| Docker 内无法执行 shell | 确认 `FH_SANDBOX_MODE` 与镜像；`FH_SANDBOX_IMAGE` 含所需工具 |
| 重启后任务状态异常 | running 僵尸会被标记 failed（预期行为），queued 会自动续跑 |
| 市场/数据集拉取失败 | 内网设镜像：`FH_SKILL_MARKET` / `FH_SWEBENCH_DATA_URL` |
