# 工程实战技能包（Engineering Skills）

> 上游项目：https://github.com/mattpocock/skills

## 触发
当用户进行真实编码工作、需要"先想清楚再动手"时使用：需求含糊、要写测试、要评审代码、要优化架构、要把大任务拆小。按场景选择子技能。

## 执行步骤

### 子技能 1：需求拷问（grill-me）
- 触发：用户给的目标过于笼统（"做个 XX 系统"）。
- 步骤：逐条追问 —— 谁是使用者？验收标准？边界（不做什么）？数据来源？性能/规模？失败场景？
- 输出：一份可执行的明确需求清单。

### 子技能 2：测试驱动开发（TDD）
- 触发：用户要求"先测试后实现"或修复 bug。
- 步骤：先写失败的测试 → 最小实现通过 → 重构；每步跑测试。
- 输出：红/绿/重构三步记录 + 最终测试结果。

### 子技能 3：代码评审
- 触发："帮我 review / 检查这个改动"。
- 步骤：定位改动范围 → 按正确性/安全/可维护性/性能逐项检查 → 分级输出问题。
- 输出：🔴严重 / 🟡建议 / 🟢优化 分级清单，每条给位置+建议。

### 子技能 4：架构优化
- 触发："架构有点乱 / 怎么重构更好"。
- 步骤：梳理现状 → 找耦合/重复/坏味道 → 给渐进式重构方案（不一次性推翻）。
- 输出：现状-目标-分步迁移计划。

### 子技能 5：任务拆解
- 触发："这个大功能怎么落地"。
- 步骤：按依赖顺序拆成可独立完成的小任务，标注每步验收点。
- 输出：编号任务清单，每项含范围+验收+预估。

## 通用原则
- 需求不清晰绝不直接写代码，先拷问。
- 每个子技能结束时给一个"下一步"。
- 适配 GitHub/Linear 等任务追踪时，把输出同步为结构化任务项。
